# HTTP API and metrics

The dashboard, JSON API, and Prometheus metrics share one listener, `http.listen` (default `127.0.0.1:8080`). With host networking it is an address on the host. Auth, roles, and tokens: [auth.md](auth.md). Dashboard pages: [ui.md](ui.md). Keys: [CONFIG.md](CONFIG.md).

## Endpoints

| Path | Body |
|---|---|
| `/` | Overview (#170): the mode banner (first on every page; observe says it announces nothing), tiles, and the setup checklist. Each area has its own URL under the left navigation: improvements, prefixes and ASNs, reports, providers, troubleshooting, settings, the events and audit log page (#173), and the pages that are still empty states. See [docs/ui.md](ui.md). When the controller cannot be reached, the page says so and keeps the last data, marked stale. |
| `/api/overview` | The dashboard's summary: mode, readiness, counts, per-provider probe results, optional features on or off, and the setup checklist (`setup`: `id`, `level` `todo`/`warn`/`info`, `title`, `detail`, `doc`). |
| `/api/system` | Per-component health (#184): `summary` counts by state and `components` (`kind`, `name`, `type`, `state` `ok`/`degraded`/`down`/`idle`, `since`, `error`, `detail`). Viewer; read-only; no secrets ([ui.md](ui.md#system-health)). `/api/overview` carries the same `summary` as `system`. |
| `/api/search` | Global search (#172): `?q=` is a prefix, address, AS number, or AS name. Lists `asns`, `measured`, `rib`, `recommendations`, `improvements`, and `rollups`, each `{total, rows}`, 25 rows at most (`asns` by AS number, the others newest first). Viewer; read-only; `400` for other input, `429` past 10 at once then 2 a second per caller; stored lists are empty and `history.note` says so without `storage` ([ui.md](ui.md#global-search)). |
| `/healthz` | Liveness. JSON `status` is `ok`. |
| `/readyz` | Readiness. 503 until startup finishes, and until an iBGP session is up when neighbors are configured. |
| `/metrics` | Prometheus text. |
| `/api/providers` | Providers, probe-source health, and BGP sessions. |
| `/api/probes` | Latest probe per provider and prefix. |
| `/api/prefixes` | Probed prefixes with measurements, current exit, and recommended exit, one page at a time (`limit` up to 500, default 100; `offset`, `prefix`, `asn`, `provider`, `differs`, `sort`; [ui.md](ui.md#prefix-list)). Prefixes that are only in the RIB are not listed. |
| `/api/decisions` | Latest per-prefix decision. |
| `/api/improvements` | Active improvements, each with `volume_mbps` when a target source reports the prefix rate. In observe and suggest these are recommendations. In inject they are the routes being announced. |
| `/api/commit` | Viewer. `?days=1`, `7` (default), or `30`; anything else is a `400`. Per telemetry binding: the `/api/telemetry` fields, `billable_mbps` (the figure commit control compares with the commit), `points` (`at`, `mbps` the busiest sample of the point, `p95_mbps` the running 95th of the billing period, `new_period` on the first point of a period), and `moves` (commit improvements that took traffic off the provider or put it on: `at`, `direction` `off` or `onto`, `peer`, `prefixes`, `announced` true only for a record made in inject). A point is 5 minutes, 30 minutes, or 2 hours wide for 1, 7, or 30 days. `samples_stored` and `moves_recorded` say whether the storage plugin keeps the samples and the improvements. `billable_mbps` is absent without a stored sample or a positive commit. `moves_truncated` is true when the improvement history is longer than one report returns (10000 rows) and the moves are incomplete. Read-only (#174). |
| `/api/exchanges` | Viewer. Per exchange: `lans`, `prefixes`, `improvements`, and `peers` (`asn`, `next_hop`, `via`, `prefixes`, `up`, `adj_rib_in` from BMP statistics when seen, `improvements`, `moved_mbps`, `moves` with `prefix`, `since`, and `volume_mbps`, `observed_asn` when it differs, and `reach`: `state`, `loss_pct`, `rtt_ms`, `degraded`, `checked` from the next-hop probe, #149), `degraded`, `degraded_peers`, and `degraded_since` for the exchange, and `discovered` LAN members. Each peer has `availability`: prefixes through its next hop seen `route_server_only`, `bilateral_only`, or `both`, and a `flag` (`rs_partial`, `rs_missing`) when the route server feed lacks prefixes it sends bilaterally. Read-only (#148, #149, #156, #147). |
| `/api/exchanges/member` | Viewer. `?exchange=<name>&next_hop=<ip>` for a configured peer: `availability` and `history` (counts every 15 minutes, up to 3 days, kept in memory). `&class=route_server_only\|bilateral_only\|both` adds `prefixes` (first `limit`, default 100, max 1000) and `prefixes_total`. `400` for a bad parameter, `404` for a next hop that is not a peer of that exchange. Read-only (#156). |
| `/api/exchanges/offload` | Viewer. Prefixes whose exit is a transit while a configured exchange peer advertises the exact prefix (the route check passes), sorted by bytes: `rows` with `prefix`, `bytes`, `mbps`, `transit`, `peers` (`exchange`, `peer`), and `est_savings` (the transit's `cost` times `mbps`, absent when the transit has no `cost`). `prefixes`, `bytes`, `mbps`, and `est_savings` total all candidates; `truncated` is true when `rows` was cut at `limit` (default 100, max 1000; the CSV defaults to 1000). `?format=csv` downloads the rows. The exit is the RIB's best path, or the active improvement's provider in `inject`; volume comes from target sources that report it. `400` for a bad parameter, `404` without exchanges. Read-only (#152). |
| `/api/lookup` | Viewer. The PeeringDB / IX-F cache when `lookup` is configured (#153): `configured`, `anonymous`, `base_url`, `fetched`, `stale`, `error`, `network_count`, `membership_count`, `exchanges` (`name`, `ix_id`, `ix_name`, `city`, `country`, `ixf_url`, `error`, `ixf_error`), `networks` (`asn`, `name`, `org`, `policy`, `policy_url`, `info_prefixes4`, `info_prefixes6`; an absent hint is omitted and a zero is a real zero), and `memberships` (`exchange`, `asn`, `name`, `ipv4`, `ipv6`, `route_server`). `?asn=` (a number or `AS64496`) keeps one network and its memberships. Empty lists and `configured: false` when it is not. The API key is not included. Read-only. |
| `/api/ixp/members` | Viewer. The IX-F member list when `ixp.members` is configured (#161): `configured`, `url`, `manager`, `key_id`, `key_expires`, `fetched`, `stale`, `error`, `member_count`, `address_count`, `ixps`, and `members` (ASN, name, connections, LAN addresses, route-server flag, `max_prefix`, `as_macro`, switch and colo from that connection's IXP). Empty lists and `configured: false` when it is not. The API key is not included. Read-only. |
| `/api/ixp/probes` | Viewer. The latest fabric round when `ixp.fabric` is configured (#162): `configured`, `stale`, `error`, `round`, `targets`, `opt_out`, `vantages` (`name`, `address`, `vlan_id`, `up`, `targets`, `error`), and `samples` (vantage, ASN, address, loss, RTT, jitter, busy-host, past the ping warning, switch and colo). Empty lists and `configured: false` when it is not. The API key is not included. Read-only. Nothing is announced. |
| `/api/exchanges/potential-peers` | Viewer. Destination origin ASNs ranked by flow bytes: `rows` with `asn`, `class`, `bytes`, `mbps`, `prefixes` (with traffic), `lan_prefixes` and `lan_bytes` (those with a learned path whose next hop is on an exchange LAN today), and `members` (`exchange`, `peer` for a configured peer, `next_hop`, `via`). `class` is `route_server` (a member with that AS has paths via a route server), `bilateral` (members seen only bilaterally), `unknown` (on a LAN, session type not visible), or `absent` (no peer or LAN member has that AS). `?class=` keeps one class; `asns`, `bytes`, and `mbps` total it, `classes` counts every class, and `unattributed_bytes` had no covering learned route or belong to the local AS. `limit` as for the offload report; `?format=csv` downloads the rows. The origin AS is the last AS of the covering learned route. `400` for a bad parameter, `404` without exchanges. Read-only (#154). |
| `/api/telemetry` | Interface rates and 95th-percentile usage when a telemetry plugin is configured. Empty when it is not. This does not announce. |
| `/api/reports` | The report list with each report's `category`, `summary`, `filters`, and `columns`, and whether history storage is on. |
| `/api/reports/<name>` | One report as JSON, or CSV or XLSX with `?format=csv` or `?format=xlsx`. Range: `?days=7` (default), or `from` and `to` as RFC 3339 or `YYYY-MM-DD` (UTC). `limit`. Filters, where the report takes them: `provider`, `asn` (`AS64510` or `64510`), `prefix` (a network in CIDR form), `cause`, `ip_version` (`4` or `6`) (#172, #178). `sort` is a column key (with `order=asc\|desc`) or, for `prefixes`, `asns`, and `countries`, `problems\|volume\|loss`. Any other parameter, or a filter the report does not take, is a `400`. Reports: `summary`, `improvements`, `exchanges` (improvements onto each exchange peer with Mbps moved), `causes`, `performance` (loss and latency before and after), `providers` (efficiency), `prefixes`, `asns`, `countries`, `probes` (per day), `savings`, `timeseries` (before/after loss and latency per day and bucket, drawn on `/graphs.html`), `mitigations`, `anomalies`. The filters per report are in [ui.md](ui.md#reports). Needs `storage`. |
| `/api/troubleshoot` | Which troubleshooting tools are on ([CONFIG.md](CONFIG.md#troubleshoot)). |
| `/api/troubleshoot/lookingglass?prefix=<prefix or address>` | Learned route for exactly that prefix, the longest covering route, and learned more-specifics (up to 100). Read from the RIB view; always on. |
| `/api/troubleshoot/probe` | `POST {"target":"<address or hostname>"}`. Resolves a hostname (`host`, `addresses`, and the `target` used), probes the address from every provider with the prober chain, and adds the covering learned `route`, the `current` exit, and the `best` measured exit. A provider that gets no reply is traced and its highest stable hop is probed (`indirect`). The result is returned only; it does not feed decisions. Needs `troubleshoot.enabled`. |
| `/api/troubleshoot/optimize` | `POST {"target":"<address or hostname>"}`, operator. Queues the learned prefix covering the target as an urgent probe target for 10 minutes. The decision engine still applies every rule to the result ([docs/ui.md](ui.md#troubleshooting-results)). Needs `troubleshoot.enabled`. |
| `/api/troubleshoot/traceroute` | `POST {"target":"<address>","provider":"<optional name>"}`. UDP traceroute from each provider's source. Needs `troubleshoot.enabled`. |
| `/api/troubleshoot/whois` | `POST {"query":"<address, prefix, or ASN>"}`. RDAP lookup through `troubleshoot.whois`. Needs `troubleshoot.enabled`. |
| `/api/mitigations` | Threat mitigation rules (RTBH, BGP redirect, FlowSpec drop/rate-limit/redirect), the catalog, the mitigation allowlist, and the feed of recent changes. `POST {"prefix","action","target","ttl","reason"}` (FlowSpec adds `match`, `source_countries`, `rate_mbps`) adds a rule and `DELETE /api/mitigations/<id>` removes one, when `mitigation` is configured and basic auth is on ([docs/mitigation.md](mitigation.md)). Lab-proven only. |
| `/api/leaks` | Leak watch (#199): `state` (`watching` or `unknown`), each source's health, and the prefixes held out because a route was seen outside the AS. `POST /api/leaks/clear {"prefix"}` releases one, with auth ([docs/leak-watch.md](leak-watch.md)). |
| `/api/ha` | Active/standby role (#31): `role` (`active` or `standby`), `holder`, `eligible`, `detail`, `takeovers`. `ha_enabled: false` and `role: active` when `ha` is not configured ([docs/ha.md](ha.md)). |
| `/api/federation` | Central view of every federated instance (#30): this instance's published snapshot, each peer's freshness, last error, snapshot, and inter-DC RTT, and the global commits with each member's usage. Read-only. `enabled: false` when `federation` is not configured ([docs/multi-pop.md](multi-pop.md)). |
| `/api/me` | Who you are: `auth` (`rbac`, `basic`, or `off`), `user`, `role`, `method`. |
| `/api/tokens` | Your API tokens (an admin sees all). `POST {"name","role","ttl"}` creates one and returns its secret once; `DELETE /api/tokens/<id>` revokes one. Needs `auth` ([docs/auth.md](auth.md)). |
| `/api/users` | Admin only. Users and roles. `POST {"name","role","password"}`, `PATCH /api/users/<name>` (`role`, `password`, `disabled`), `DELETE /api/users/<name>`. Needs `auth`. |
| `/api/audit` | Admin only. The audit log, newest first: `?limit=` (1–1000, default 100), `from`, `to` (RFC 3339). Needs a `storage` plugin. |
| `/auth/login`, `/auth/callback`, `/auth/logout` | OIDC single sign-on when `auth.sso` is set. |
| `/api/config` | Admin only, with `http.config_editor: true` and auth or basic auth (#34, #102). `GET` returns the mounted config file and its `sha256`; `POST /api/config/validate {"yaml"}` runs the start checks; `PUT {"yaml","base","confirm_inject"}` writes it (needs the `sha256` it edits, and `confirm_inject` to turn inject on). Applies on restart. `POST /api/config/form` reads or merges the settings form into YAML without writing; its `commit` section holds the commit setup (#174). `GET /api/config/suggestions` lists iBGP or BMP next hops that are not providers (a draft row only; it does not probe or announce). `POST /api/config/wizard` renders an observe config from the setup wizard (edge session, provider rows, optional pinned probe host, optional flow collector; inject is not a step). The settings form also edits every `flow`, `vip`, and `outage` source and every `rules` policy (#130, #226). UI: `/settings.html` ([docs/ui.md](ui.md)). |
| `/api/dashboards` | Your custom dashboards and the widget catalog (#34). `PUT /api/dashboards/<name>` saves one (layout fields `w`, `h`, `refresh`, and `favorite`: [ui.md](ui.md#custom-dashboards)), `DELETE` removes it. Needs a storage plugin and auth or basic auth. UI: `/dashboards.html`. |
| `/api/upgrade` | Admin only. Running version, install type, the last release check, and the rollback target (#196). `POST /api/upgrade/check` lists GitHub releases and changes nothing; `POST /api/upgrade/apply {"tag","confirm":true}` and `POST /api/upgrade/rollback {"confirm":true}` switch versions after the SIGTERM shutdown path has withdrawn every route. Need `upgrade.enabled`, `upgrade.public_key`, and auth or basic auth ([docs/ui.md](ui.md#upgrade-from-the-ui)). |
| `/api/subscriptions` | Report subscriptions (#34): schedule, next and last send, errors. `POST /api/subscriptions/<name>/send` (operator) sends one now. |
| `/api/maintenance` | Open, upcoming, and finished maintenance windows. `POST` opens an on-demand window and `DELETE /api/maintenance/<id>` closes one, when a `maintenance` policy is configured and basic auth is on ([CONFIG.md](CONFIG.md#policy-maintenance)). |

## Metrics

Prometheus metrics are `packeteer_up`, `packeteer_ready`, `packeteer_build_info`, `packeteer_provider_up`, `packeteer_probe_success`, `packeteer_probe_rtt_seconds`, `packeteer_probe_rtt_min_seconds`, `packeteer_probe_rtt_max_seconds`, `packeteer_probe_loss_ratio`, `packeteer_probe_jitter_seconds`, `packeteer_probe_prefix_commits`, `packeteer_flow_prefixes_tracked`, `packeteer_truncated_total`, `packeteer_decisions`, `packeteer_decision`, `packeteer_improvements_active`, `packeteer_improvement`, `packeteer_estimated_savings`, `packeteer_bgp_configured`, `packeteer_bgp_ready`, `packeteer_rib_prefixes`, `packeteer_bgp_session_up`, `packeteer_bgp_session`, and, when telemetry is configured, `packeteer_telemetry_up`, `packeteer_telemetry_in_bps`, `packeteer_telemetry_out_bps`, `packeteer_telemetry_in_95th_bps`, `packeteer_telemetry_out_95th_bps`, `packeteer_telemetry_usage_bps`, `packeteer_telemetry_commit_bps`, and `packeteer_telemetry_samples`.

When `lookup` is configured, `/metrics` also has `packeteer_lookup_networks`, `packeteer_lookup_memberships`, `packeteer_lookup_up`, and `packeteer_lookup_age_seconds`. The counts are zero while the cache is stale; age stays. They are absent when it is not configured.

When `ixp.members` is configured, `/metrics` also has `packeteer_ixp_members`, `packeteer_ixp_member_addresses`, `packeteer_ixp_member_import_up`, `packeteer_ixp_member_import_age_seconds`, and, when `key_expires` is set, `packeteer_ixp_api_key_expiry_seconds` (Unix time). Member and address gauges are zero while the list is stale. They are absent when the import is not configured.

When `ixp.fabric` is configured, `/metrics` also has `packeteer_ixp_fabric_up`, `packeteer_ixp_fabric_targets`, `packeteer_ixp_fabric_opt_out`, `packeteer_ixp_fabric_past_tolerance`, and `packeteer_ixp_fabric_age_seconds`. Targets and the past-tolerance count are zero while the member list is stale; age stays. They are absent when fabric probes are not configured. There is no per-member series.

Scrape `http://127.0.0.1:8080/metrics` on the host. With `auth` on, use an API token ([auth.md](auth.md)).
