# HTTP API and metrics

The dashboard, JSON API, and Prometheus metrics share one listener, `http.listen` (default `127.0.0.1:8080`). With host networking it is an address on the host. Auth, roles, and tokens: [auth.md](auth.md). Dashboard pages: [ui.md](ui.md). Keys: [CONFIG.md](CONFIG.md).

## Endpoints

| Path | Body |
|---|---|
| `/` | Overview (#170): the mode banner (first on every page; observe says it announces nothing), tiles, and the setup checklist. Each area has its own URL under the left navigation: improvements, prefixes and ASNs, reports, providers, troubleshooting, settings, the events and audit log page (#173), and the pages that are still empty states. See [docs/ui.md](ui.md). When the controller cannot be reached, the page says so and keeps the last data, marked stale. |
| `/api/overview` | The dashboard's summary: mode, readiness, counts, per-provider probe results and measured health (`state` `up`/`degraded`/`down`/`unknown`, `problems`), optional features on or off, the setup checklist (`setup`: `id`, `level` `todo`/`warn`/`info`, `title`, `detail`, `doc`), and `auth` (`rbac`, `basic`, or `off`; the UI warns on `off`, #328). |
| `/api/system` | Per-component health (#184): `summary` counts by state and `components` (`kind`, `name`, `type`, `state` `ok`/`degraded`/`down`/`idle`, `since`, `error`, `detail`). `kind` `rpki` rows come from the configured `rpki.sources` (#158). Viewer; read-only; no secrets ([ui.md](ui.md#system-health)). `/api/overview` carries the same `summary` as `system`. |
| `/api/search` | Global search (#172): `?q=` is a prefix, address, AS number, or AS name. Lists `asns`, `measured`, `rib`, `recommendations`, `improvements`, and `rollups`, each `{total, rows}`, 25 rows at most (`asns` by AS number, the others newest first). Viewer; read-only; `400` for other input, `429` past 10 at once then 2 a second per caller; stored lists are empty and `history.note` says so without `storage` ([ui.md](ui.md#global-search)). |
| `/healthz` | Liveness. JSON `status` is `ok`. |
| `/readyz` | Readiness. 503 until startup finishes, and until an iBGP session is up when neighbors are configured. |

| `/api/providers` | Providers, probe-source health, and BGP sessions. |
| `/api/providers/stats` | Viewer. Per provider, the median latency, loss, and jitter over the last 15 minutes and 24 hours, hourly `points`, and `mbps` when `flow` is true (a flow source reports volume) (#349). See [ui.md](ui.md#provider-figures-and-overview-charts). |
| `/api/probes` | Latest probe per provider and prefix. |
| `/api/prefixes` | Probed prefixes with measurements, current exit (the learned path in observe and suggest, the engine's choice in inject), and recommended exit, one page at a time (`limit` up to 500, default 100; `offset`, `prefix`, `asn`, `provider`, `differs`, `sort`; [ui.md](ui.md#prefix-list)). | `/api/decisions` | Latest per-prefix decision. Each `candidates` entry carries `rpki` (`valid`, `invalid`, `notfound`, `unknown`) when the `rpki` block is on (#158). |
| `/api/improvements` | Active improvements, each with `volume_mbps` when a target source reports the prefix rate. In observe and suggest these are recommendations. In inject they are the routes being announced. Each also has `explain` (the reason as a plain sentence, quoting a threshold only when the latest measurements beat it; `reason` stays the short record), `native_loss_pct`, `loss_pct`, `native_rtt_ms`, `rtt_ms`, `gain_ms`, `gain_pct`, and `loss_gain_pct` (omitted when loss reads equal) from the latest probe round (omitted without a usable measurement for both providers), `hold_left_s` while `hold_time` has not elapsed, and `asn` and `as_name` of the origin (#348). |
| `/api/commit` | Viewer. `?days=1`, `7` (default), or `30`; anything else is a `400`. Per telemetry binding: the `/api/telemetry` fields, `billable_mbps` (the figure commit control compares with the commit), `points` (`at`, `mbps` the busiest sample of the point, `p95_mbps` the running 95th of the billing period, `new_period` on the first point of a period), and `moves` (commit improvements that took traffic off the provider or put it on: `at`, `direction` `off` or `onto`, `peer`, `prefixes`, `announced` true only for a record made in inject). A point is 5 minutes, 30 minutes, or 2 hours wide for 1, 7, or 30 days. `samples_stored` and `moves_recorded` say whether the storage plugin keeps the samples and the improvements. `billable_mbps` is absent without a stored sample or a positive commit. `moves_truncated` is true when the improvement history is longer than one report returns (10000 rows) and the moves are incomplete. Read-only (#174). |
| `/api/exchanges` | Viewer. Per exchange: `lans`, `prefixes`, `improvements`, and `peers` (`asn`, `next_hop`, `via`, `prefixes`, `up`, `adj_rib_in` from BMP statistics when seen, `improvements`, `moved_mbps`, `moves` with `prefix`, `since`, and `volume_mbps`, `observed_asn` when it differs, and `reach`: `state`, `loss_pct`, `rtt_ms`, `degraded`, `checked` from the next-hop probe, #149), `degraded`, `degraded_peers`, and `degraded_since` for the exchange, `port` when the exchange has one (`state` `ok`, `stale`, or `no_telemetry`; `capacity_mbps`, `commit_mbps`, `port_cost`, `load_mbps`, `p95_mbps`, `headroom_mbps`, #151), and `discovered` LAN members. Each peer has `availability`: prefixes through its next hop seen `route_server_only`, `bilateral_only`, or `both`, and a `flag` (`rs_partial`, `rs_missing`) when the route server feed lacks prefixes it sends bilaterally. With the `rpki` block on, each peer also has `rpki`: its prefixes counted `valid`, `invalid`, `notfound`, and `unknown` (#158). Read-only (#148, #149, #156, #147). |
| `/api/exchanges/member` | Viewer. `?exchange=<name>&next_hop=<ip>` for a configured peer: `availability` and `history` (counts every 15 minutes, up to 3 days, kept in memory). `&class=route_server_only\|bilateral_only\|both` adds `prefixes` (first `limit`, default 100, max 1000) and `prefixes_total`. `400` for a bad parameter, `404` for a next hop that is not a peer of that exchange. Read-only (#156). |
| `/api/exchanges/offload` | Viewer. Prefixes whose exit is a transit while a configured exchange peer advertises the exact prefix (the route check passes), sorted by bytes: `rows` with `prefix`, `bytes`, `mbps`, `transit`, `peers` (`exchange`, `peer`), and `est_savings` (the transit's `cost` times `mbps`, absent when the transit has no `cost`). `prefixes`, `bytes`, `mbps`, and `est_savings` total all candidates; `truncated` is true when `rows` was cut at `limit` (default 100, max 1000; the CSV defaults to 1000). `?format=csv` downloads the rows. The exit is the RIB's best path, or the active improvement's provider in `inject`; volume comes from target sources that report it. `400` for a bad parameter, `404` without exchanges. Read-only (#152). |
| `/api/lookup` | Viewer. The PeeringDB / IX-F cache when `lookup` is configured (#153): `configured`, `anonymous`, `base_url`, `fetched`, `stale`, `error`, `network_count`, `membership_count`, `exchanges` (`name`, `ix_id`, `ix_name`, `city`, `country`, `ixf_url`, `error`, `ixf_error`), `networks` (`asn`, `name`, `org`, `policy`, `policy_url`, `info_prefixes4`, `info_prefixes6`; an absent hint is omitted and a zero is a real zero), and `memberships` (`exchange`, `asn`, `name`, `ipv4`, `ipv6`, `route_server`). `?asn=` (a number or `AS64496`) keeps one network and its memberships. Empty lists and `configured: false` when it is not. The API key is not included. Read-only. |
| `/api/herd` | Viewer. Herd status (#260): `enabled` (false when herd is off), this node's `key_id` and `public_key`, `asn`, `country`, `granularity`, `classes`, `sources`, `retention_days`, each peer (`url`, `key_id`, `source` of `config`, `hub`, or `snapshot`, `asn`, `last_ok`, `last_error`, `failures`, `retry_at`, `records_pulled`, `records_rejected`), `limit_trips` by limit and peer, the hand-off `queue` (`dropped`, `stored`, `restarts`), and `store` bytes and records against their budgets. Rows from a peer you removed are left out. |

A provider that gets no reply is traced and its highest stable hop is probed (`indirect`). The result is returned only; it does not feed decisions. Needs `troubleshoot.enabled`. |
| `/api/troubleshoot/optimize` | `POST {"target":"<address or hostname>"}`, operator. Queues the learned prefix covering the target as an urgent probe target for 10 minutes. | `POST /api/federation/push` | Admin only, with `http.config_editor: true`, auth or basic auth, and `federation` (#137). Only `thresholds` and `policies` are accepted; another section is a 400. | `/api/maintenance` | Open, upcoming, and finished maintenance windows. `POST` opens an on-demand window and `DELETE /api/maintenance/<id>` closes one, when a `maintenance` policy is configured and basic auth is on ([CONFIG.md](CONFIG.md#policy-maintenance)). |

## Metrics

Prometheus metrics are `packeteer_up`, `packeteer_ready`, `packeteer_build_info`, `packeteer_provider_up`, `packeteer_probe_success`, `packeteer_probe_rtt_seconds`, `packeteer_probe_rtt_min_seconds`, `packeteer_probe_rtt_max_seconds`, `packeteer_probe_loss_ratio`, `packeteer_probe_jitter_seconds`, `packeteer_probe_prefix_commits`, `packeteer_flow_prefixes_tracked`, `packeteer_truncated_total`, `packeteer_go_mutex_wait_seconds_total` (Go runtime lock wait since start, #383), `packeteer_decisions`, `packeteer_decision`, `packeteer_improvements_active`, `packeteer_improvement`, `packeteer_estimated_savings`, `packeteer_bgp_configured`, `packeteer_bgp_ready`, `packeteer_rib_prefixes`, `packeteer_bgp_session_up`, `packeteer_bgp_session`, and, when telemetry is configured, `packeteer_telemetry_up`, `packeteer_telemetry_in_bps`, `packeteer_telemetry_out_bps`, `packeteer_telemetry_in_95th_bps`, `packeteer_telemetry_out_95th_bps`, `packeteer_telemetry_usage_bps`, `packeteer_telemetry_commit_bps`, and `packeteer_telemetry_samples`.

After the preflight checks have run, `/metrics` has `packeteer_preflight_ready`, `packeteer_preflight_check{check,status}`, and `packeteer_preflight_last_run_timestamp_seconds`.

When `lookup` is configured, `/metrics` also has `packeteer_lookup_networks`, `packeteer_lookup_memberships`, `packeteer_lookup_up`, and `packeteer_lookup_age_seconds`. The counts are zero while the cache is stale; age stays. They are absent when it is not configured.

When `ixp.members` is configured, `/metrics` also has `packeteer_ixp_members`, `packeteer_ixp_member_addresses`, `packeteer_ixp_member_import_up`, `packeteer_ixp_member_import_age_seconds`, and, when `key_expires` is set, `packeteer_ixp_api_key_expiry_seconds` (Unix time). Member and address gauges are zero while the list is stale. They are absent when the import is not configured.

When `ixp.fabric` is configured, `/metrics` also has `packeteer_ixp_fabric_up`, `packeteer_ixp_fabric_targets`, `packeteer_ixp_fabric_opt_out`, `packeteer_ixp_fabric_past_tolerance`, and `packeteer_ixp_fabric_age_seconds`. Targets and the past-tolerance count are zero while the member list is stale; age stays. They are absent when fabric probes are not configured.

With the same fabric probes (#166), `/metrics` has `packeteer_ixp_member_rtt_ms`, `packeteer_ixp_member_loss_pct`, and `packeteer_ixp_member_jitter_ms` with labels `asn`, `vlan`, `vantage`, and `family`: the latest round, the worst address per VLAN and family. A probe error and a stale member list make no series. There is one series per member, vantage, and family, so a large exchange needs the Prometheus capacity for that.

When `ixp.routeservers` is configured, `/metrics` also has `packeteer_ixp_rs_up`, `packeteer_ixp_rs_sessions_established`, `packeteer_ixp_rs_sessions_down`, `packeteer_ixp_rs_filtered_routes`, and `packeteer_ixp_rs_age_seconds`. A stale server counts as down and its sessions are not counted. There is no per-member series.

When `ixp.correlate` is configured, `/metrics` also has `packeteer_ixp_fabric_groups_degraded` (switches, colos, and bundles with an open `ixp.fabric_degraded`) and `packeteer_ixp_members_degraded` (members with an open `ixp.member_degraded`). There is no per-member or per-group series.

With federation on an IXP-mode instance (#167), `/metrics` also has `packeteer_ixp_site_up` and `packeteer_ixp_site_incidents` (label `site`), and `packeteer_ixp_core_rtt_ms` and `packeteer_ixp_core_loss_pct` (labels `site`, `peer`, `link`). A link that could not be probed has no RTT or loss series.

Scrape `http://127.0.0.1:8080/metrics` on the host. With `auth` on, use an API token ([auth.md](auth.md)).
