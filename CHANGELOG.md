# Changelog

All notable changes to Packeteer are documented here. Versions are Git tags on `main`. The image tags `ghcr.io/grandarcher/packeteer:<version>` (for example `:0.5.0`) and `:latest` are published from each `v<version>` tag. `:edge` tracks `main`.

## [Unreleased]

### Fixed

- Exchange peering LANs are not probe targets (#145). A prefix inside `exchanges[].lans`, or a pinned host on one, is omitted from every target source. Flow and span destinations on a LAN are dropped before aggregation, so a /64 LAN does not become an `aggregate_v6` probe prefix. Traceroute does not adopt a hop on a LAN and does not trace a prefix or host inside one. A provider next hop on the LAN is still the far-side gateway probe. `allowlist.prefixes` that overlap a LAN (equal, more specific, or a supernet) fail config load in every mode. `packeteer_exchange_lan_targets_dropped` counts the omissions. Nothing is announced. The learned-RIB check, improvement cap, community and NO_EXPORT, hold time, and withdraw rules are unchanged. No new config key. Rollback: revert this change. A config that overlaps a LAN will then load, and LAN addresses can be probed again.

- Exchange session type (#146). A route-server label is no longer applied to every exchange peer. `via` on each learned path, and on each peer in `/api/exchanges`, is `route_server`, `bilateral`, or `unknown`. A BMP neighbor on the exchange LAN whose address is not the path's next hop is the route server, and the MED label names that neighbor. A neighbor equal to the next hop is bilateral. An iBGP add-path path or a Loc-RIB path stays unknown until BMP paths for that next hop agree; when both types are seen the peer stays unknown. MED stays display-only. The learned-RIB check, allowlist, cap, community and NO_EXPORT, hold time, route check, and withdraw rules are unchanged. No new config key. Nothing is announced. Rollback: none needed.

- Load-test RSS growth budget (#120). Actions run 37698413398 measured 258 MiB of growth after warmup against the 256 MiB `pr` budget. The warmup median was 4590 MiB and the second-half median was 4849; RSS then fell from 4966 to 4827 and stayed there. End RSS and peak (4967) sat with the same day's green `main` runs (ends 4806, 4863, and 4835; peaks 4954 to 5100). The `pr` budget is 384 MiB. A second half that stays 400 MiB above warmup still fails the check. Peak RSS and the weekly soak budget are unchanged. No announce-path change. Rollback: none needed.

- Improved prefixes stay probe targets (#116). While an improvement is active, its prefix stays in the probe set with the last host and interval after every configured source drops it (for example it falls out of flow `top_n`). It is not withdrawn for that. It still withdraws on flip-back, `improvement_ttl`, a provider that is down or unusable, a confirmed RIB leave, policy, the allowlist, stale measurements, probe-source loss, RIB session loss, and shutdown. When the improvement retires and no source lists the prefix, the next completed round drops the target. Observe stays the default. Rollback: revert this change; a prefix that leaves every source is then withdrawn on the next decision instead of staying probed.

- Flow probe hosts are candidates, not pins (#113). The busiest destination in a flow prefix, and a problem address, is probed first, then the automatic in-prefix addresses and a usable provider next hop, at most four per provider. A silent address drops out of the score when another address inside the prefix answers, so one eyeball or NAT address that ignores ICMP and TCP/443 no longer makes every provider look like 100% loss. An operator `host` on `static`, `vip`, or `traceroute` is still the only address probed. Nothing is announced. Every packet still waits on `probe.rate_limit_pps`. Rollback: none needed; the previous behavior pinned the flow host and skipped the other addresses.

### Added

- Flow volume floor and priority tiers (#118). A prefix stays eligible when its bytes in the window reach `min_bytes` or its share of those bytes reaches `min_pct`. Zero turns that bar off. With both at zero every prefix with bytes is eligible and `top_n` still cuts the list, which is the previous behavior. Eligible prefixes are largest first, with equal totals broken by prefix text. `top_n` is the priority tier and is probed every `probe.interval`. `max_targets` (0 or omitted matches `top_n`, and it cannot exceed 10000 or sit below `top_n`) is the larger set. Prefixes past `top_n` carry `tail_interval`, which is required then. The controller refuses to start unless that interval is longer than `probe.interval` and shorter than the staleness window, so a tail measurement cannot sit stale. Problem prefixes stay ahead of the list and keep the normal interval. The commit scorer still sees every prefix in the window. Nothing is announced. Observe stays the default. The learned-RIB check, allowlist, cap, community and NO_EXPORT, hold time, and withdraw rules are unchanged. Every packet still waits on `probe.rate_limit_pps`. Rollback: omit the new keys (or set `min_pct` to 0 and leave `max_targets` at `top_n`). The probed list is then the previous top `top_n` above `min_bytes`, and nothing is withdrawn by this change.

- Host qualification (#119). `probe.min_replies` (default 1, bounds 1–1000) is how many replies a host needs before it can define a prefix. `probe.dispersion_ms` (default 0, bounds 0–600000) is the widest RTT spread, slowest reply minus fastest, that still qualifies. A spread equal to the limit qualifies. One reply has a spread of zero. Zero disables the spread check. An unqualified host is left out of the score the way a silent host is. When no host qualifies, every measured host still counts so the loss is reported. A spread over the limit also runs the existing retry with `probe.retry_packets` (filled to three times `packets`, capped at 1000, when dispersion is set and `retry_packets` is 0). Too few replies do not escalate. The retry sample replaces the first, runs once, and still waits on `probe.rate_limit_pps`. The staleness window grows by `retry_packets * timeout` only when that second probe can run. `min_replies` alone does not. For a flow prefix, up to three of the busiest destinations in the window are candidates, probed first, still under the four-per-provider cap with the next-hop slot. Automatic in-prefix addresses fill in only when flow named fewer than three. Each time bucket keeps the three destinations with the most bytes in that bucket. A problem address stays first, then the busiest destinations, still at most three. An operator pin is still the only address. Nothing is announced. Observe stays the default. The learned-RIB check, allowlist, cap, community and NO_EXPORT, hold time, and withdraw rules are unchanged. Rollback: revert this change. Omitting the keys (or setting `min_replies` to 1 and `dispersion_ms` to 0) restores the previous score and withdraws nothing; the three flow destinations stay until the change is reverted.

- Prober memory (#120). The engine remembers the prober that got a reply from each host and starts the next round there. The chain moves forward from that prober. Every `probe.prober_recheck_rounds` measurement (default 10; the 1st, 11th, 21st, …) starts at the first prober again, so a host that begins answering ICMP is noticed. `probe.prober_memory` (default 100000) caps the hosts remembered; the least recently probed are dropped, and a host that leaves the probe set is dropped on the next completed round. Providers share one entry per host. When they first get replies from different probers in one round, the later prober in the chain is kept. A loss retry uses the same start and does not advance the schedule. Every prober that runs still waits on `probe.rate_limit_pps`. On-demand troubleshooting still walks the full chain and does not change this memory. Nothing is announced. Observe stays the default. Rollback: revert this change, or set `probe.prober_recheck_rounds` to 1 so every round starts at the first prober. That withdraws nothing.

- RTT percent and confirm rounds before a new performance move (#117). `thresholds.min_rtt_delta_pct` (0–100, default 0, off) makes an RTT win need both `min_rtt_delta_ms` and that percent of the current path's RTT. A loss win ignores the percent. `thresholds.confirm_rounds` (1–100, omitted or 0 means 1) waits for that many consecutive fresh probe rounds before a new performance move or a switch is created. A stale round does not count and does not reset the streak; the same measurements seen again are not a new round; a fresh miss resets it, including a performance switch off a commit or cost steer. Wins on every performance switch count during `hold_time`; the switch is created only after `hold_time`. While the streak is short and the evaluation compared the paths, the prefix is probed again after a quarter of its probe interval, still inside `probe.rate_limit_pps`. A round that cannot compare keeps the streak and does not ask for that early probe. Flip-back, static pins, commit moves, and cost moves do not wait. Defaults match the previous one-round, milliseconds-only rule. Every move still goes through Decide (exact learned prefix, allowlist, cap, community + NO_EXPORT, hold time, and the withdraw rules). Observe stays the default. The settings form shows both keys. Rollback: revert this change, or omit the keys (or set the percent to 0 and rounds to 1); new moves then announce on the first fresh win again. Setting the keys back off does not withdraw a route that is already up.

- MED on each learned path, and an ASN map of measured prefixes (#105). Each path on a measured prefix, including an inactive add-path or BMP path, shows its next hop, AS path, and MED. The MED label names who advertised it (the iBGP neighbor or the BMP peer). A route server is named only when the path came through one (#146), by that neighbor's address; a bilateral peer is not called a route server. MED is not a step in path selection and is not an input to the exit: the decision stays probes plus cost and commit. The ASN map groups those measured prefixes by origin ASN and by provider site (name and next hop). A site is marked partial when another site of the same provider carries a measured prefix it does not. Paths for prefixes that are not being measured are not exported. No announce-path change. Rollback: none needed.


- Automatic probe targets (#104). A prefix with no host is measured at a few addresses inside it (the first host, and on a larger prefix a quarter point and a halfway point, at most three) plus that provider's next hop when the next hop is a usable far-side address. At most four addresses per provider per prefix. A configured host is a pin and is the only target; a host named by an earlier source stays, and a later named host replaces a default. One silent in-prefix address does not define the loss or latency when another in-prefix address answered. The next hop is the score only when every in-prefix address was silent, so a one-hop gateway does not hide the prefix. Nothing is announced, the next hop is not turned into a provider, and traceroute hop times are not the score. The addresses are on each probe result (`targets`) for a lab check. No announce-path change. Rollback: set `host` on each target to keep the old single address.

- Setup wizard (#106). `/settings.html` walks three steps: the learn-only edge session (ASN, router ID, address), provider rows the operator adds (plus and minus; a BGP suggestion only fills the next hop), then an optional prefix with an optional pinned probe host. `POST /api/config/wizard` still writes nothing and always returns `mode: observe`, with an empty allowlist, no announcer, and one iBGP neighbor. Inject is not a step; any other mode is refused. A prefix without a host is probed at its first address. Secrets stay in environment variables; the wizard has no secret fields. No announce-path change. Rollback: none needed; keep editing the YAML.
- Opt-in 3 million prefix lab profile (#103; lab only). `routes3m` in `lab/soak/budgets.yaml` is the `pr` observe workload with a 3,000,000-prefix synthetic table (documentation prefixes, IPv6 half at /54). A human passes the name to `lab/soak.sh`. The `load` job still runs `pr` (1,250,000 prefixes and its existing budgets) and `soak.yml` still runs `soak`. `routes3m` budgets are empty until a run on a large host records learn time, RSS, and API latency; they are reported and not checked. No announce-path change. Rollback: none needed.
- Settings form beside the YAML editor (#102). `/settings.html` edits providers (name, probe source, next hop, cost, commit), static probe prefixes, the allowlist, and the decision knobs (hold time, improvement cap, loss and latency thresholds, and on the cost scorer whether cost or performance wins plus the extra-loss and extra-delay floor) with plus and minus rows. `POST /api/config/form` merges that into the YAML without writing; save is still `PUT /api/config` with the start checks, `confirm_inject`, and apply-on-restart. Secrets stay in environment variables. `GET /api/config/suggestions` lists iBGP or BMP next hops that are not configured providers and not on an exchange LAN; accepting one adds a draft row (next hop and AS only) and does not write, probe, or announce. No announce-path change. Rollback: none needed; leave the form unused and keep editing the file.

## [0.5.0] - 2026-10-01

Fifth release: hardening and polish (#49–#53). UI/UX polish so a first run is readable (mode banner, overview tiles, setup checklist, empty and error states); install and walkthrough docs that CI runs (single-container quickstart, observe → suggest → inject on a simulated edge, troubleshooting, MikroTik/FRR/Junos/Cisco router guides); load and soak budgets under a full-table synthetic RIB, a fix for flow ingest when that window is full, and an RSS growth check that does not treat a Go heap refill as a leak; a MikroTik CHR lab in QEMU on CI runners; and a scheduled router interop matrix (FRR, BIRD 2/3, and GoBGP edges against iBGP, add-path, and BMP, plus CHR). Lab-proven only, against simulated routers in CI with documentation prefixes and private ASNs, not on a public edge. Safety rules are unchanged: the default stays `mode: observe`, an announcement still needs the exact prefix in the learned RIB, the allowlist, the configured community and NO_EXPORT, the improvement cap, and hold time, and CI still proves announce, withdraw, and crash-withdraw. Field feedback from real observe-mode deployments (#54) is still open.

### Added

- Router interop matrix in the lab (#53; lab only). New `interop` workflow (weekly, on demand, and on PRs that touch the lab, the announcer, or the BMP station). It runs `lab/e2e-interop.sh` for every cell of FRR 10.2, BIRD 2, BIRD 3, and GoBGP edges against iBGP best path, add-path, and BMP post-policy (BIRD 2 has no BMP), plus the RouterOS CHR lab. Each simulated edge (`lab/interop/`) sits between the Packeteer image and two FRR transits. `lab/interopcheck` reads each router's own show output. Each cell checks that the edge's best path is Packeteer's exact learned prefix with the provider next hop, local-pref 250, `64512:666`, and `no-export`, that nothing reaches the transits, and that allowlisted prefixes no router advertised are never announced. It also checks flip-back, the route-check retire on a transit withdraw (add-path and BMP), SIGTERM, a frozen process held until the 9s hold timer, and SIGKILL. Interop finding, documented in [docs/routers.md](docs/routers.md#interop-matrix): BIRD 3.1.7's BMP does not refeed sessions that were already up when the station reconnects. No Packeteer code or announce-path change. Rollback: none needed.
- MikroTik CHR lab in CI (#52; lab only). ### Fixed

- Load-test RSS growth check (#97). The `pr` profile compared medians of the first and last tenth after warmup, about 35 seconds each. On a ~4.5 GiB heap that window is shorter than Go's return-and-refill cycle (`MADV_DONTNEED`), so a valley read as growth: Actions run 36902639588 failed at 342 MiB (baseline 4476, end 4818) while the end sat in the 4609–4818 band of the runs that passed and peak RSS stayed under 6144. Growth is now the median of the second half after warmup minus the median during warmup. Across those nine `ubuntu-latest` runs that figure was at most 146 MiB, so the 256 MiB budget stays. Peak RSS is unchanged and the `load` job still enforces it. No announce-path change. Rollback: none needed.
- Flow ingest under a full-table flow mix (#51). Once a `flow` window bucket held its 20,000 prefixes, every new prefix rescanned all of them, so at 20,000 records a second with a full table 78.8 % of flow datagrams were dropped. A full bucket now frees its smallest sixteenth in one pass (never a prefix larger than the newcomer), and the anomaly counters prune idle keys at most once a minute while at their cap. Drops fell to 1.8 % and CPU from 1.2 to 0.72 cores in the same test. The busiest prefixes are still the ones kept.

## [0.4.0] - 2026-09-30

Fourth release: the v0.4 IRP-parity milestone (#30–#34). Multi-POP federation with routing domains, inter-DC RTT, global commit, and a central view; active/standby HA with a lease elector plus config and history backup/restore; user accounts, RBAC, API tokens, access restriction, an audit log, and OIDC SSO for the ops API; flow-baseline anomaly (DDoS) detection that alerts by default and mitigates only through explicit rules and the existing mitigation controller; and the remaining UI parity (improvement weights, a validated config editor and first-run wizard, custom dashboards, email report subscriptions). The BGP-facing parts are lab-proven against FRR/GoBGP in CI with documentation prefixes and private ASNs, not on a public edge. The default stays `mode: observe`; every new block is off unless configured, and a remote-POP steer, an HA takeover, or a detector rule still needs the exact prefix in the learned RIB, the allowlist, the community + NO_EXPORT, the cap, and hold time. CI still proves announce, withdraw, and crash-withdraw.

### Added

- Remaining UI parity (#34; improvement weights lab-proven only). **Improvement weights**: new optional `improvement_weights` (`performance`, default 1; `volume`, default 0) on the `weighted`, `commit`, and `cost` scorers (`plugin.ImprovementWeigher`) admits new static, VIP, and performance moves to `max_improvements` by `performance × gain + volume × Mbps` inside their lane; it never admits a prefix outside the learned RIB or allowlist, never exceeds the cap, and never displaces an active improvement; the weight is on `/api/decisions`; FRR lab `lab/e2e-weights.sh`. **Config editor**: `http.config_editor` (default `false`) lets an admin read, validate, and write the mounted config file (`/api/config`, `/settings.html`) after the same checks as a start, with an optimistic `base` hash, `confirm_inject` to turn inject on, read-back through `config.Load`, and an audit record by hash; it applies on restart (or SIGHUP for `bgp.neighbors`). It never runs an `exec` plugin (plugins are built check-only, new `plugin.Env.CheckOnly`) and refuses a file that adds or changes one or changes `plugin_dir`; `GET /api/config` is unredacted, so keep secrets in env vars. **First-run wizard** (behind `http.config_editor` too): `POST /api/config/wizard` renders an observe-mode config with an empty allowlist for review. **Custom dashboards**: per-user widget layouts in the `sqlite` store (`plugin.DashboardStore`, `/api/dashboards`, `/dashboards.html`). **Email report subscriptions**: new `report_subscriptions` email a stored report as CSV on a daily, weekly, or monthly UTC schedule through an `smtp` notifier (`plugin.ReportSender`); `/api/subscriptions` shows state and operators can send one now. Guide: [docs/ui.md](docs/ui.md). Rollback: remove `improvement_weights`, `http.config_editor`, and `report_subscriptions` and restart.
- Automatic traffic anomaly (DDoS) detection (#33; lab-proven only). New `detector` plugin kind (`pkg/plugin`, in-process only, never announces) with the built-in `baseline` detector: an EWMA mean and variance per destination prefix and IP protocol, with `sensitivity`, `min_ratio`, `min_mbps`, an optional `max_mbps` ceiling, `warmup`, `trigger_rounds`/`clear_rounds`, and a `max_keys` bound; attack rounds are not learned. The `flow` source now implements `plugin.FlowCounterSource` (bounded per-prefix, per-protocol byte counters; protocol is decoded for sFlow too). On its own `anomaly.interval` the core logs every anomaly and exposes it on `GET /api/anomalies` (200-entry feed), `anomaly.*` events, `packeteer_anomal*` metrics, and sqlite history (`/api/reports/anomalies`). It acts only on explicit `anomaly.rules`, only through the #28 mitigation controller (its `mode`, allowlist, `max_rules`, TTL, community, NO_EXPORT), only for an exact learned-RIB prefix, capped (`max_active`) and rate-limited (`max_actions_per_hour`), never on an HA standby, and never replacing an operator's rule. The rule is removed on clear, and all anomalies clear after 3 failed flow reads. Rule prefixes must sit inside `mitigation.allowlist`, and rules without `mitigation` refuse to start. Guide: [docs/anomaly.md](docs/anomaly.md). Tests: detector, controller, config, flow counter, API, and history unit tests; the docker job runs the stock image with an anomaly block; the FRR lab (`lab/e2e-anomaly.sh`, synthetic NetFlow) proves no action without a rule, never announcing a rule prefix outside the learned RIB, FlowSpec drop with NO_EXPORT on a learned prefix, withdraw on clear, and withdraw on RIB session loss, SIGTERM, and SIGKILL. Rollback: remove `anomaly.rules` (alerts only) or the `anomaly` block and restart.
- User accounts, RBAC, access restriction, audit log, and optional SSO for the ops HTTP server (#32). New `auth` block (`enabled`, `session_ttl`, `token_ttl`, `sso`) and `http.allow_from`. Roles `viewer` (read, own API tokens), `operator` (maintenance windows, mitigation rules, troubleshooting tools), and `admin` (users, audit log); every route has a minimum role and `/healthz`, `/readyz`, and `/auth/*` are public. Users (PBKDF2 password hashes) and API tokens (`pkt_...`, SHA-256 hashes, capped at one year and 20 per user, never above the user's role, cannot mint tokens) live in the storage plugin through the new optional `plugin.UserStore` and `plugin.AuditStore` (`sqlite` implements both). The first admin comes from `PACKETEER_ADMIN_USER`/`PACKETEER_ADMIN_PASSWORD`. New `sso` plugin kind with the built-in `oidc` (authorization code + PKCE, ID token verified, groups mapped to roles; client secret from the environment). New endpoints `/api/me`, `/api/users`, `/api/tokens`, `/api/audit`, `/auth/login`, `/auth/callback`, `/auth/logout`. Every change, denied change, SSO sign-in and sign-out, bootstrap, and SIGHUP reload is written to the audit log (log, store, and a new `audit.recorded` event, trap ID 26), with and without `auth`. Failed sign-ins are throttled per address; cross-site browser changes are refused. Tests: an authorization test that walks every route with anonymous, bad-token, viewer, operator, and admin callers, API tests for users, tokens, audit, SSO, `allow_from`, and legacy mode, an OIDC test against an in-process identity provider, and sqlite store tests. No announce-path change. Rollback: `auth.enabled: false` (basic-auth account, or read-only bound to localhost). Guide: [docs/auth.md](docs/auth.md).
- High availability: active/standby with config and history backup (#31; lab-proven only). New optional `ha` block and elector plugin kind (`pkg/plugin.Elector`) with the built-in `lease` elector: two instances with the same config share a lease file on a volume both mount (`path`, `id` or `PACKETEER_HA_ID`, `ttl`, `renew`). Only the active instance runs decisions and announces; the outbound, inbound, and mitigation controllers check the elector under their locks before every sync, so a standby withdraws anything left and never announces. An instance may lead only while its RIB view is ready. On becoming standby an instance withdraws at once, drops its decision state, and resigns, so the other takes over at its next renewal (SIGTERM, session loss). After a crash the standby waits until the lease has not changed for `ttl`/2 plus the holder's recorded negotiated BGP hold time, so the routers have dropped the old routes first; the active instance stops announcing `ttl`/2 after its last renewal even if its loop is stuck. `/api/ha`, `packeteer_ha_active`, `packeteer_ha_eligible`, `packeteer_ha_takeovers`, and events `ha.standby` and `ha.active` (trap IDs 24–25). New `packeteer -backup FILE` (config file plus a consistent copy of the `sqlite` history, safe while running; never overwrites) and `-restore FILE` (validates the archived config, restores the history; `-restore-config PATH`, `-force`), through the optional `plugin.StorageBackup`. Guide: [docs/ha.md](docs/ha.md). Tests: lease unit tests (exclusive activity, crash wait, resign, ineligibility, stuck loop, restart), gate tests for all three controllers, a daemon test with two controllers against a simulated GoBGP edge, and a new FRR lab (`lab/e2e-ha.sh`) proving the standby never announces, SIGKILL takeover only after the edge dropped the old route, session-loss handover, SIGTERM handover, a clean final withdraw, and backup/restore in the stock image, with the edge never holding routes from both. ## [0.2.0] - 2026-09-28

Second release: the v0.2 IRP-parity milestone (#15–#24). More probing (UDP, traceroute discovery, retry, outage detection), SNMP telemetry and 95th-percentile commit control, cost-aware routing, routing policies and maintenance windows, passive problem detection, alerts, reports and history, and read-only troubleshooting tools. The default stays `mode: observe`; every new capability is off unless configured, and injection still requires the learned RIB, the allowlist, the community, the cap, and hold time. CI still proves announce, withdraw, and crash-withdraw against FRR with documentation prefixes.

### Added

- Troubleshooting tools (#24). `/api/troubleshoot/lookingglass` shows the learned route for a prefix, the longest covering route, and learned more-specifics. With `troubleshoot.enabled: true`, `POST /api/troubleshoot/probe` probes one address from every provider with the prober chain, `POST /api/troubleshoot/traceroute` runs a UDP traceroute from each provider's source, and `POST /api/troubleshoot/whois` looks up an address, prefix, or ASN through the new `whois` plugin kind (built-in `rdap`). The dashboard has a Troubleshooting section. Requests are rate limited (`requests_per_minute`, default 6), need basic auth when it is on, and refuse loopback, link-local, multicast, and unspecified targets. The tools are read-only: on-demand results never reach the decision loop and nothing announces. The looking glass is always on; the rest are off by default.
- Reports and history (#23). New `storage` plugin kind with the `sqlite` built-in (embedded, pure Go, file on the `/var/lib/packeteer` volume, `retention` default 400 days). The controller records daily probe rollups per prefix and provider, one row per improvement with before (native) and after (chosen provider) loss and latency, and per-prefix origin ASN, country, and volume. `/api/reports/<name>` serves `summary`, `improvements`, `causes`, `performance`, `providers`, `prefixes`, `asns`, `countries`, `probes`, and `savings` as JSON or CSV (`?format=csv`), and the dashboard has a Reports section. History is written once a minute and on shutdown after the withdraw; a storage failure never delays or withdraws an improvement. Storage does not announce. Off unless `storage` is set; the example config sets it.
- Alerts and notifications (#22). A documented event catalog ([docs/EVENTS.md](docs/EVENTS.md)) with severities, SNMP trap IDs, and dedup keys: improvement added, switched, and removed; provider (probe source) down and up; iBGP session down and up; commit exceeded and cleared; announcer sync failed and recovered; outage incidents; controller started and stopping. New `smtp` notifier (STARTTLS required by default, credentials from the environment) and `snmptrap` notifier (SNMPv2c or v3, secrets from the environment). The `webhook` notifier gains `slack`, `teams`, and `pagerduty` presets (problems trigger, recoveries resolve the same dedup key) and a `template` body for SMS and other gateways. Every notifier, `exec` included, takes `events`, `min_severity`, and `rate_limit`. Each notifier has its own bounded queue, so a slow or failing notifier never delays probing, decisions, or withdrawals. Notifiers never announce. Off unless `notifiers` is configured.
- Passive problem detection (#21). The `span` target source reads a SPAN/mirror port with AF_PACKET (`NET_RAW`, host networking) or replays a classic pcap, follows TCP connections between your `local` networks and remote addresses, and scores remote prefixes by retransmissions, handshake timeouts, remote resets, and optionally handshake RTT. Problem prefixes are probed first. The `flow` source gains an optional `problems` block that scores the same failures from TCP flags on unsampled NetFlow v5/v9 and IPFIX. Neither announces. Off unless configured.
- Routing policies (`policies`). The `rules` policy matches by prefix, origin ASN, or country (a MaxMind-format database you mount) and applies `ignore`, `allow`, `deny`, `static`, or `vip`. A prefix match beats an ASN match, which beats a country match; the longest prefix wins, then list order. The `maintenance` policy excludes providers during cron-scheduled, one-off, or on-demand windows (`POST /api/maintenance`, basic auth required). Decisions show the matched policy. Every verdict still goes through the RIB, allowlist, cap, and withdraw rules. A `static` rule requires `max_loss_pct` (optional `max_rtt`): the pin is announced and held only while its path stays inside that ceiling, and switching an existing improvement onto it waits out `hold_time`. Pins expire on `improvement_ttl` like other improvements and return next round if the prefix is still in the RIB. On-demand maintenance windows are in memory only and end on restart; configure planned windows in `windows`. Off unless listed.
- `snmp` telemetry plugin. Polls interface octet counters over SNMP v2c or v3 and tracks 95th-percentile usage for the open UTC billing period (`separate`, `greater`, and `greater_separate`). Credentials are environment variables. The collector does not announce. Samples are in memory and are cleared on restart. `/api/telemetry` and `packeteer_telemetry_*` expose them.
- `commit` scorer. Keeps each provider's billable 95th under its commit by moving prefixes that have flow volume onto a provider with room, and can balance a provider group (`equal` or `proportional`). `precedence` orders destinations and is the last resort; sharing a group does not outrank it. A move that increases loss is refused unless `loss_override` is set, and Decide enforces that for every planner. A commit steer whose loss clears `min_loss_delta_pct` is withdrawn and waits out `hold_time`. A smaller gap stays. Improvements are tagged `performance` or `commit`, share `max_improvements` (a new performance move can displace the smallest commit steer), and still require the learned RIB. The default scorer remains `weighted`. Switching back and restarting withdraws commit improvements.
- `cost` scorer and `providers[].cost`. Moves a prefix to the cheapest priced provider whose path is inside a performance floor (`floor.max_loss_pct`, `floor.max_rtt`, measured from the best path) and cheaper than native. `precedence: performance` (default) lets performance moves win; `precedence: cost` keeps a native path inside the floor and prefers the cheapest in-floor path over the fastest. Decide re-checks the floor and the price and withdraws a cost steer at once when it leaves the floor. Improvements are tagged `cost`, share `max_improvements`, and still require the learned RIB and the allowlist. `/api/improvements` reports `cost_delta` and `est_savings`, and `packeteer_estimated_savings` sums them. The default scorer remains `weighted`; switching back and restarting withdraws cost improvements. The FRR lab has a cost-cause announce, withdraw, and SIGKILL job.
- `fixed` telemetry plugin, for labs and tests. It reports a configured billable figure and can re-read a file. It does not poll and it does not announce.
- Static targets accept an optional `mbps` rate so commit control can run without a flow export. The FRR lab has a commit-cause announce, withdraw, and SIGKILL job.
- `outage` target source. Probe results inside a window are correlated by learned AS path and by provider. Enough prefixes failing together re-queues the affected prefixes (capped) and emits `outage.as` or `outage.circuit`. One prefix does not. The source does not announce.
- `udp` prober. A datagram reply counts. An ICMP destination-unreachable counts only when the sender is the target, so a firewall `REJECT` is loss. It is not in the default chain. A TCP RST from a middlebox is still indistinguishable from the target.
- `traceroute` target source. When the configured host does not answer, probes move to the last stable hop. The prefix is unchanged and the hop is not announced. Discovery runs in the background, returns the last cache immediately, and is capped by `budget` (default 10s).
- `vip` target source. Prefixes, and prefixes whose learned AS path contains a listed ASN, are probed on their own interval. `max_targets` (default 100) caps the list. The expansion is rebuilt only when the RIB changes. The interval must be shorter than the staleness window, and it cannot slow a prefix another source already listed. The global packet rate limit still applies. ASN matches wait until the RIB is ready.
- Retry probing. `probe.retry_loss_pct` (default off) re-measures a lossy sample with `probe.retry_packets` before it is stored.

## [0.1.0] - 2026-09-25

First release. An observe-first BGP path performance controller in one container. Injection is opt-in and is tested in CI against FRR with documentation prefixes (RFC 5737) and the private ASN 64512.

### Added

- Probe engine. ICMP echo and TCP connect (port 443), sourced from each provider, with a worker pool and a global packet-rate cap. Loss, RTT min/avg/max, and jitter.
- Target sources: a static prefix list, and a flow collector for NetFlow v5/v9, IPFIX, and sFlow v5 (top prefixes by bytes).
- Learn-only iBGP RIB view on an embedded GoBGP speaker. Graceful restart is not enabled. The speaker proposes a 90s hold time.
- Decision engine with a weighted scorer, loss and latency thresholds, hold time, a cooldown after flip-back, an improvement cap (default 50), and an improvement TTL.
- Inject mode. The `gobgp` announcer publishes the exact learned prefix on that same iBGP session, with the provider next hop, `local_pref`, the configured community, and `no-export`.
- Withdraw on shutdown, on a dead probe source, on stale measurements (including a probe round that never finishes), when every BGP session is down, and when a prefix the router was still advertising leaves the RIB. A best-path hide is kept so the route does not flap.
- Read-only HTTP surface on `127.0.0.1:8080`: dashboard, `/healthz`, `/readyz`, Prometheus `/metrics`, and a JSON API. Optional basic auth from the environment.
- Plugin host: prober, source, scorer, announcer, and notifier. Built-ins plus `exec` and `webhook`. Announcers stay in-process.
- Container image (linux/amd64, linux/arm64) and a Compose file. Config is a mounted file.
- FRR lab. The e2e job checks announce, flip-back, withdraw while the controller is alive, clean shutdown, and SIGKILL (the route is gone within the BGP hold timer).
- Operator quick start, config reference, router filters (MikroTik, FRR, Junos, IOS), and policy routing.

### Safety

- The shipped example and Compose instructions stay `mode: observe`.
- Inject requires `mode: inject`, a non-empty allowlist, a community, `local_pref`, a positive hold time, positive loss and latency thresholds, an announcer, and an iBGP neighbor.
- Packeteer does not announce a prefix that is absent from the learned RIB. `more_specific_bits` is rejected.
- Learned routes are not reflected. The export policy accepts only Packeteer's own routes that carry the community.
- No graceful restart.

### Known limitations

- On a best-path-only iBGP session the router stops advertising a prefix once Packeteer's route wins. A provider withdraw after that point is caught at `improvement_ttl`, unless the router keeps sending the native path (`advertise-best-external` on FRR and IOS). Additional paths and BMP are later.
- `observe` and `suggest` share one code path. Neither announces. Recommendations are the log, the dashboard, and `/api/decisions`.
- No inbound optimization, FlowSpec, RTBH, SNMP, commit or cost control, alerts beyond the webhook notifier, reports, or high availability.
- The flow collector is unauthenticated UDP. Firewall it to the exporter.
- The HTTP server is read-only and has no accounts or audit log. It defaults to loopback.
- Communities are RFC 1997 (two 16-bit integers). `router_id` is IPv4.
- RouterOS, Junos, and IOS snippets are documentation. The automated BGP test is the FRR lab.
