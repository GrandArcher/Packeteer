Setup wizard

Four steps, the last one optional. It always starts in observe: the edge session is learn-only, and the allowlist stays empty. A fresh file has no announcer; over an existing config, blocks the wizard does not write are kept. Inject is not a step. Secrets stay in environment variables; this wizard has no secret fields. Nothing is written until you save the YAML below.

This config already has providers, BGP neighbors, or an ixp block. Running setup again replaces its providers, BGP neighbors, sources, allowlist, scorer, and decision settings. Sign-in, the http block, storage, and every other block are kept. You see a diff and confirm before anything reaches the editor.

The iBGP session Packeteer learns from. It does not announce.

Add each provider yourself. Plus adds a row and minus removes one. A suggestion only fills the next hop; you still name it and set the probe source. Nothing is probed or announced until you save and restart.

Optional. Leave both empty to add probe targets later. A prefix without a host is probed at a few addresses inside it, including the provider next hop when that address can be used. A host pins that prefix to one address.

Optional flow collector. Leave it off to add a flow source later. When on, Packeteer listens on this UDP address and port for NetFlow v5/v9, IPFIX, or sFlow records and probes the busiest destination prefixes. It measures only and never announces.

Exporter setup: on the router, send flow records to this host and port (for example NetFlow v9 or IPFIX to the address below). With --network host this is a host UDP port; do not publish it, and allow it only from the router. Packeteer does not configure the router.

Leave this unticked to keep sign-in as it is. Ticked, the generated config sets auth.enabled to false.

A provider needs a telemetry binding (an SNMP host and interface) to have a commit; the community is read from an environment variable named here, never typed in. Observe stays the default. The result shows on Commit & Cost.

          Settings forms
          
    
          Everything is a form here. Save merges your changes into the file, runs the same checks as a start, and writes it; the Preview below shows the difference and which changes need a restart first. Keys the form does not know are kept exactly as they are, and a form you did not change writes nothing. Thresholds, hold time, the improvement cap, policies, sources, probe timing, mode, the allowlist, and BGP neighbors apply on Save. Any other change waits for a restart. Turning inject on needs the checklist and a confirmation. Secrets stay in environment variables: the form asks for the variable's name, never the secret. The raw YAML is the last section, for anything the forms do not show. Needs http.config_editor: true and the admin role.

          Providers
          
        
          Plus adds an empty row. Minus removes one. Cost is the price per Mbps. Commit is the telemetry binding's commit, set up in the Commit setup above; the form does not ask for an SNMP community or any other secret. BMP use says whether paths from the BMP station count for that provider.
          
        
          
        
        
          Suggestions from BGP
          
        
          Next hops on iBGP or BMP that are not configured providers. Accept adds a draft row with the next hop and the AS filled in. Probe source, cost, and commit stay empty. Accepting does not save, does not probe, and does not announce. Exchange LAN hops are offered under Discovered members in Exchanges instead.
          
        
          
          
        
          
        
          
        
          
        
          
        
          Exchanges
          
        
          Every exchange: its peering LANs and the peers on them. A peer is a provider with its own next hop on a LAN. It is always route-checked, so a BGP neighbor needs add-path, or BMP use must be prefer or only with a BMP station; Save checks that. The probe source of a peer is required before Save. Exclude and precedence are under each peer's Show advanced. Add one LAN per row. No session or route-server credential is asked for. Nothing is probed or announced until you save and restart.
          
        
          
        
        
          Discovered members
          
        
          Next hops on an exchange's peering LAN that are not peers, as the running controller sees them. Accept adds a draft peer with the AS and next hop filled in. Name, probe source, and cost stay empty. Accepting does not save, does not probe, and does not announce. Only an exchange that is already running lists members.
          
        
          
          
        
          
        
          
        
          Prefixes to probe
          
        
          The first static source. Other source types are under Plugins.
          
        
          
        
        
          Allowlist
          
        
          Prefixes that may be injected. Empty means nothing may be announced.
          
        
          
        
        
          Flow collectors
          
        
          Every flow source (NetFlow v5/v9, IPFIX, sFlow). It measures only. A second source needs its own name and listen address. Removing a source removes it, including its problem, transit, and sub-range settings, which are under each source's Show advanced. Each listen address and each excluded prefix is its own row. Binds host UDP ports with --network host; do not publish them.
          
        
          
        
        
          Policies (rules)
          
        
          Every rules policy, in file order. A policy only restricts or pins what the decision engine may choose: the learned-RIB check, allowlist, cap, hold time, and withdraw rules still apply. Policies and the rules in them are evaluated in the order shown. A second policy needs its own name. Providers, prefixes, ASNs, and countries are picked one at a time. A country rule needs a GeoIP database: an absolute path to a file mounted in the container; Packeteer does not fetch it. Removing a policy removes it. Maintenance windows are below; other policy types are under Plugins.
          
        
          
        
        
          
        
          VIP
          
        
          Every vip source: critical prefixes and ASNs probed on their own interval. Removing a source removes it.
          
        
          
        
        
          Outage detection
          
        
          Every outage source: when many prefixes fail together it re-probes them and raises an event. It never announces. Empty fields use the defaults. Removing a source removes it.
          
        
          
        
        
          Inbound optimization …
          
        
          The inbound block (docs/inbound.md). Observe logs steers and announces nothing. The form never turns inbound inject on: do that in the raw YAML after the inject checklist, and Save asks you to confirm it. Unchecking removes the block, announcer included. Each prefix is its own row. Each trigger you moderate is only suggested, even in inject. The announcer is set below. 
          
        
          
          
          
          
          Your prefixes
          Prefixes this network originates. Pick one learned with an empty AS path, or add a prefix.
          
          
          
          
          
          
          
          
          
          
          
          
          
          
          
        
          
        
          
        
          
        
          
        
          Anomaly rules …
          
        
          The anomaly rules (docs/anomaly.md). A rule turns a detected anomaly into a mitigation rule, and only the mitigation controller acts on it: its mode, allowlist, rule cap, and learned-RIB check apply.  The first matching rule wins. Rules need the detector above to be on.
          
        
          
        
          
        
        
          
        
          Plugins
          
        
          Probers, notifiers, telemetry, storage, and the sources and policies that have no card above. Untick one to remove it on Save; the Preview shows what goes. Show settings lists its plain settings. A key that may hold a secret is listed by name and never shown, and a nested value is kept as it is.

              Version and upgrade
              
    
              Shows the running version. With upgrade.enabled: true and upgrade.public_key it also reads GitHub releases, upgrades to the one you pick, and rolls back. Nothing upgrades by itself: Check only lists releases, and an upgrade needs your confirmation. The release's signed checksum file and the binary are verified before anything changes, and the new version must pass its start check against this config. Then Packeteer shuts down as it does on SIGTERM, which withdraws every Packeteer route, and the new version starts in the configured mode and learns the RIB again before it injects. The config file is not touched. Admin role.
