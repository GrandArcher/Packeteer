Setup wizard

Four steps, the last one optional. It always starts in observe: the edge session is learn-only, the allowlist stays empty, and there is no announcer. Inject is not a step. Secrets stay in environment variables; this wizard has no secret fields. Nothing is written until you save the YAML below.

  2. 2. Providers
  3. 3. Probe
  4. 4. Flow (optional)

The iBGP session Packeteer learns from. It does not announce.

Add each provider yourself. Plus adds a row and minus removes one. A suggestion only fills the next hop; you still name it and set the probe source. Nothing is probed or announced until you save and restart.

Optional. Leave both empty to add probe targets later. A prefix without a host is probed at a few addresses inside it, including the provider next hop when that address can be used. A host pins that prefix to one address.

Optional flow collector. Leave it off to add a flow source later. When on, Packeteer listens on this UDP address and port for NetFlow v5/v9, IPFIX, or sFlow records and probes the busiest destination prefixes. It measures only and never announces.

Exporter setup: on the router, send flow records to this host and port (for example NetFlow v9 or IPFIX to the address below). With --network host this is a host UDP port; do not publish it, and allow it only from the router. Packeteer does not configure the router.

    Settings

    The form edits providers, probe prefixes, the allowlist, the flow, VIP, and outage sources, the rules policies, and the knobs that change a decision. The YAML stays beside it: anything the form does not show is kept. Apply copies the form into the YAML and does not write the file. Save runs the same checks as a start. Thresholds, hold time, the improvement cap, policies, sources, probe timing, mode, the allowlist, and bgp.neighbors apply on Save. Any other change waits for a restart. Turning inject on still needs the confirmation. Secrets stay in environment variables, not in the form. Needs http.config_editor: true and the admin role.

    Decision

    Providers

    Plus adds an empty row. Minus removes one. Cost is the price per Mbps. Commit is the telemetry binding's commit; the form does not ask for an SNMP community or any other secret.

    Suggestions from BGP

    Next hops on iBGP or BMP that are not configured providers. Accept adds a draft row with the next hop and the AS filled in. Probe source, cost, and commit stay empty. Accepting does not save, does not probe, and does not announce. Exchange LAN hops stay on the exchange view until you add them as peers.

    Prefixes to probe

    The first static source. Other sources stay in the YAML.

    Allowlist

    Prefixes that may be injected. Empty means nothing may be announced.

    Flow collector

    The first flow source (NetFlow v5/v9, IPFIX, sFlow). It measures only. Unchecking removes the source from the YAML, including its problems, transit, and subranges blocks; those blocks and the aggregate lengths are otherwise kept. Separate several listen addresses and exclude prefixes with commas. Binds host UDP ports with --network host; do not publish them.

    Policies (rules)

    The first rules policy. A policy only restricts or pins what the decision engine may choose: the learned-RIB check, allowlist, cap, hold time, and withdraw rules still apply. Rules keep their order. Provider, prefix, ASN, and country lists are comma separated. Removing every rule removes the policy. geoip_db, maintenance windows, and other policies stay in the YAML.

    VIP

    The first vip source: critical prefixes and ASNs probed on their own interval. Unchecking removes the source.

    Outage detection

    The first outage source: when many prefixes fail together it re-probes them and raises an event. It never announces. Empty fields use the defaults. Unchecking removes the source.

    Inbound optimization …

    The inbound block (docs/inbound.md). Observe logs steers and announces nothing. The form never turns inject on: that is a YAML edit after the inject checklist, and Save asks you to confirm it. Unchecking removes the block, announcer included. Separate lists with commas. Each trigger you moderate is only suggested, even in inject. The announcer (inbound.announcer) stays in the YAML.

    Anomaly rules …

    The anomaly.rules list (docs/anomaly.md). A rule turns a detected anomaly into a mitigation rule, and only the mitigation controller acts on it: its mode, allowlist, rule cap, and learned-RIB check apply. The first matching rule wins. The detector, source, and caps stay in the YAML, and the form cannot add a detector.
