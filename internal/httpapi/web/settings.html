    Commit setup

    Four steps to turn on commit control for the providers you pay a commit on, then review the YAML. It works on the settings form below and writes the YAML text only: nothing is saved or announced until you Save, and the scorer, telemetry, and provider changes apply after a restart. A provider needs a telemetry binding (an SNMP host and interface) to have a commit; the community is read from an environment variable named here, never typed in. Observe stays the default. The result shows on Commit & Cost.

    2. 2. Commit and telemetry
    3. 3. Groups and precedence
    4. 4. Review

    Tick each provider you pay a commit on. Its commit (Mbps) is the billing commit; the SNMP host and interface are where Packeteer reads its usage. A tracked provider cannot be untracked here: remove its binding in the YAML.

    A group shares traffic between its members when the commit scorer's balance is not off. A lower precedence is preferred; the highest is a last resort that takes commit traffic only when every lower one is full (blank means 100). Leave a provider out of commit control with cc_disable; performance moves can still use it.

        Settings

        The form edits providers, exchanges and their peers, probe prefixes, the allowlist, the flow, VIP, and outage sources, the rules policies, and the knobs that change a decision. The YAML stays beside it: anything the form does not show is kept. Apply copies the form into the YAML and does not write the file. Save runs the same checks as a start. Thresholds, hold time, the improvement cap, policies, sources, probe timing, mode, the allowlist, and bgp.neighbors apply on Save. Any other change waits for a restart. Turning inject on still needs the confirmation. Secrets stay in environment variables, not in the form. Needs http.config_editor: true and the admin role.

        Decision

        Providers

        Plus adds an empty row. Minus removes one. Cost is the price per Mbps. Commit is the telemetry binding's commit; the form does not ask for an SNMP community or any other secret.

        Suggestions from BGP

        Next hops on iBGP or BMP that are not configured providers. Accept adds a draft row with the next hop and the AS filled in. Probe source, cost, and commit stay empty. Accepting does not save, does not probe, and does not announce. Exchange LAN hops are offered under Discovered members in Exchanges instead.

        Exchanges

        Every exchanges entry: its peering LANs and the peers on them. A peer is a provider with its own next hop on a LAN. It is always route-checked, so the file needs add_path on a bgp.neighbors entry or bmp: prefer or only with rib_sources; Save checks that. The probe source of a peer is required before Save. Exclude and precedence stay in the YAML. Separate LANs with commas. No session or route-server credential is asked for. Nothing is probed or announced until you save and restart.

        Discovered members

        Next hops on an exchange's peering LAN that are not peers, as the running controller sees them. Accept adds a draft peer with the AS and next hop filled in. Name, probe source, and cost stay empty. Accepting does not save, does not probe, and does not announce. Only an exchange that is already running lists members.

        Prefixes to probe

        The first static source. Other sources stay in the YAML.

        Allowlist

        Prefixes that may be injected. Empty means nothing may be announced.

        Flow collectors

        Every flow source (NetFlow v5/v9, IPFIX, sFlow). It measures only. A second source needs its own name and listen address. Removing a source removes it from the YAML, including its problems, transit, and subranges blocks; those blocks are otherwise kept. Separate listen addresses and exclude prefixes with commas. Binds host UDP ports with --network host; do not publish them.

        Policies (rules)

        Every rules policy, in file order. A policy only restricts or pins what the decision engine may choose: the learned-RIB check, allowlist, cap, hold time, and withdraw rules still apply. Policies and the rules in them are evaluated in the order shown. A second policy needs its own name. Provider, prefix, ASN, and country lists are comma separated. A country rule needs a geoip_db: an absolute path to a database file mounted in the container; Packeteer does not fetch it. Removing a policy removes it from the YAML. Maintenance windows and other policy types stay as they are.

        VIP

        Every vip source: critical prefixes and ASNs probed on their own interval. Removing a source removes it from the YAML.

        Outage detection

        Every outage source: when many prefixes fail together it re-probes them and raises an event. It never announces. Empty fields use the defaults. Removing a source removes it from the YAML.

        Inbound optimization …

        The inbound block (docs/inbound.md). Observe logs steers and announces nothing. The form never turns inject on: that is a YAML edit after the inject checklist, and Save asks you to confirm it. Unchecking removes the block, announcer included. Separate lists with commas. Each trigger you moderate is only suggested, even in inject. The announcer (inbound.announcer) stays in the YAML.

        Anomaly rules …

        The anomaly.rules list (docs/anomaly.md). A rule turns a detected anomaly into a mitigation rule, and only the mitigation controller acts on it: its mode, allowlist, rule cap, and learned-RIB check apply. The first matching rule wins. The detector, source, and caps stay in the YAML, and the form cannot add a detector.

          Report subscriptions

          Stored reports emailed on a UTC schedule through an smtp notifier. Subscriptions and recipients live in report_subscriptions in the config file. Operators may send one now.

          Version and upgrade

          Shows the running version. With upgrade.enabled: true and upgrade.public_key it also reads GitHub releases, upgrades to the one you pick, and rolls back. Nothing upgrades by itself: Check only lists releases, and an upgrade needs your confirmation. The release's signed checksum file and the binary are verified before anything changes, and the new version must pass its start check against this config. Then Packeteer shuts down as it does on SIGTERM, which withdraws every Packeteer route, and the new version starts in the configured mode and learns the RIB again before it injects. The config file is not touched. Admin role.
