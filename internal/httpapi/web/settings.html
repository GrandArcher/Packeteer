Setup wizard

Four steps, the last one optional. It starts in observe with an empty allowlist; inject is not a step. Once the config is saved, the preflight checks below decide when injection can be offered. Blocks the wizard does not write are kept. Nothing is written until you save the YAML below.

First-run setup is pending. Saving a config here ends it. Skip setup if the file is already what you want; the editor then turns off at the next start unless http.config_editor is true.

This config already has providers, BGP neighbors, or an ixp block. Running setup again replaces its providers, BGP neighbors, sources, allowlist, scorer, and decision settings. Every other block is kept. You see a diff and confirm first.

      Preflight checks
      
    
      Settings and the API refuse to turn injection on until every check here passes. Each check says what it found and how to fix it, and the same checks run again any time. Running them reads the BGP sessions and sends one TTL-limited probe per provider toward a documentation address. The results are also in /metrics as packeteer_preflight_check.

              Providers
              
        
              Plus adds an empty row. Minus removes one. Cost is the price per Mbps. Commit is the telemetry binding's commit, set up in the Commit setup above; the form does not ask for an SNMP community or any other secret. BMP use says whether paths from the BMP station count for that provider.
              
        
              
        
        
              Suggestions from BGP
              
        
              Next hops on iBGP or BMP that are not configured providers. Accept adds a draft row with the next hop and the AS filled in. Probe address, cost, and commit stay empty. Exchange LAN hops are offered under Discovered members in Exchanges instead.
              
        
              
          
        
              
        
              
        
              
        
              
        
              Exchanges
              
        
              Every exchange: its peering LANs and the peers on them. A peer is a provider with its own next hop on a LAN. It is always route-checked, so a BGP neighbor needs add-path, or BMP use must be prefer or only with a BMP station; Save checks that. The probe address of a peer is required before Save. Exclude and precedence are under each peer's Show advanced. Add one LAN per row. No session or route-server credential is asked for.
              
        
              
        
        
              Discovered members
              
        
              Next hops on an exchange's peering LAN that are not peers, as the running controller sees them. Accept adds a draft peer with the AS and next hop filled in. Name, probe address, and cost stay empty. Only an exchange that is already running lists members.
              
        
              
          
        
              
        
              
        
              Prefixes to probe
              
        
              The first static source. Other source types are under Plugins.
              
        
              
        
        
              Allowlist
              
        
              Prefixes that may be injected. Empty means none.
              
        
              
        
        
              Flow collectors
              
        
              Every flow source (NetFlow v5/v9, IPFIX, sFlow). A second source needs its own name and listen address. Removing a source removes it, including its problem, transit, and sub-range settings, which are under each source's Show advanced. Each listen address and each excluded prefix is its own row. Binds host UDP ports with --network host; do not publish them.
              
        
              
        
        
              Policies (rules)
              
        
              Every rules policy, in file order. A policy only restricts or pins what the decision engine may choose: the learned-RIB check, allowlist, cap, hold time, and withdraw rules still apply. Policies and the rules in them are evaluated in the order shown. A second policy needs its own name. Providers, prefixes, ASNs, and countries are picked one at a time. A country rule needs a GeoIP database: an absolute path to a file mounted in the container; Packeteer does not fetch it. Removing a policy removes it. Maintenance windows are below; other policy types are under Plugins.
              
        
              
        
        
              
        
              VIP
              
        
              Every vip source: critical prefixes and ASNs probed on their own interval. Removing a source removes it.
              
        
              
        
        
              Outage detection
              
        
              Every outage source: when many prefixes fail together it re-probes them and raises an event. Empty fields use the defaults. Removing a source removes it.
              
        
              
        
        
              Inbound optimization …
              
        
              The inbound block (docs/inbound.md). Steers are logged only. The form never turns inbound inject on: do that in the raw YAML after the inject checklist, and Save asks you to confirm it. Unchecking removes the block. Each prefix is its own row. A moderated trigger is only suggested, even in inject. 
              
        
              
          
          
          
              Your prefixes
              Prefixes this network originates. Pick one learned with an empty AS path, or add a prefix.
              
          
          
          
          
          
          
          
          
          
          
          
          
          
          
        
              
        
              
        
              
        
              
        
              Anomaly rules …
              
        
              The anomaly rules (docs/anomaly.md). A rule turns a detected anomaly into a mitigation rule, and only the mitigation controller acts on it: its mode, allowlist, rule cap, and learned-RIB check apply.  The first matching rule wins. Rules need the detector above to be on.
              
        
              
        
              
        
        
              
        
              Plugins
              
        
              Probers, notifiers, telemetry, storage, and the sources and policies that have no card above. Untick one to remove it on Save; the Preview shows what goes. Show settings lists its plain settings. A key that may hold a secret is listed by name and never shown, and a nested value is kept as it is.

                  Version and upgrade
                  
    
                  Shows the running version. With upgrade.enabled: true and upgrade.public_key it also reads GitHub releases, upgrades to the one you pick, and rolls back. Nothing upgrades by itself: Check only lists releases, and an upgrade needs your confirmation. The release's signed checksum file and the binary are verified before anything changes, and the new version must pass its start check against this config. Then Packeteer shuts down as it does on SIGTERM, which withdraws every Packeteer route, and the new version starts in the configured mode and learns the RIB again before it injects. The config file is not touched. Admin role.
