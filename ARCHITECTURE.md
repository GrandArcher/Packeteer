# Architecture

```
flow/SPAN/SNMP/static prefix list
        |
        v
   prefix picker  --->  probe worker (one source per upstream)
        |                      |
        |                      v
        |               samples: loss, rtt, jitter
        |                      |
        v                      v
   RIB view (iBGP + BMP) --> routing policies (rules, maintenance)
                                   |
                                   v
                           policy engine (score + hysteresis)
                                   |
                    observe: log only
                    inject:  gobgp announcer on the same iBGP session
                             (+ inbound steers, + mitigation rules from the API or anomaly rules)
```

## Components

- **Probe worker** sources packets out each configured provider (dedicated probe address or policy-routed source). Compares the same destination across providers. Each round has an overall deadline (the same window as stale measurements, about three intervals, plus retry packets when loss retry or dispersion escalation is on). A prober or target source that ignores cancellation is abandoned; the previous results stay, and the next round waits until that call returns. Built-in probers are ICMP, TCP, and UDP. The engine remembers the prober that got a reply from each host and starts later rounds there, moving forward from that prober; every `probe.prober_recheck_rounds` measurement (default 10) starts at the first prober again. `probe.prober_memory` caps that set, and hosts that leave the probe set are dropped. An on-demand troubleshoot probe still walks the whole chain. UDP counts a datagram reply, or an ICMP destination-unreachable whose source is the target; an unreachable from another address is loss. TCP counts a SYN-ACK or a RST, and a middlebox RST is not distinguishable from the target. The traceroute source discovers in the background and returns its last cache immediately, under a budget (default 10s, max 30s) that sits under the default round deadline. It keeps the configured host if it answers and otherwise sets the probe host to the last stable hop; the prefix does not change and that hop is not announced. With `probe.indirect` on (#123), a prefix whose in-prefix addresses were all silent for a provider is traced in the background from that provider's source under its own budget; the highest stable hop is cached per prefix and provider and probed in later rounds as that provider's indirect host, marked `indirect` on the result. The vip source marks configured prefixes, and at most `max_targets` prefixes whose learned AS path contains a listed ASN, with its own interval. That interval must be shorter than the staleness window, and it never lengthens the interval of a prefix another source already listed. The ASN expansion is rebuilt only when the RIB generation changes. The scheduler probes a prefix when its interval has elapsed and keeps the other results. Sources that do not carry a shorter interval are re-read on the engine interval, not on every VIP wake. A completed round, including one that only probed VIP prefixes, still runs the decision engine. A prefix that has left every configured source is dropped on the next completed round, including a round that probes nothing, unless an improvement is still active for it. While an improvement is active the engine keeps that prefix in the probe set from the decision state, with the host and interval from the last time a source listed it. That set is applied on every round, including a short VIP wake, and is not cached for the engine interval. After the improvement retires, the next completed round drops the prefix if no source lists it. A host qualifies when it has at least `probe.min_replies` replies (default 1) and, when `probe.dispersion_ms` is set, an RTT spread (slowest reply minus fastest) no wider than that limit. An unqualified host is left out of the score the way a silent host is. A measurement whose loss is at least `probe.retry_loss_pct` (default off), or whose spread is over `probe.dispersion_ms`, is taken again with `probe.retry_packets` before it is stored; the retry sample replaces the first. Too few replies do not escalate. Both checks are off at the defaults. Every probe, including retries and the VIP cadence, waits on the global packet rate limit. The outage source reads each completed round and the learned AS path. When enough prefixes that share an ASN degrade on every measured provider, or enough prefixes degrade on one provider and stay healthy on another, it re-queues those prefixes (and, for an ASN, the other learned prefixes that cross it) up to `max_targets` and emits `outage.as` or `outage.circuit`. One prefix does not. The probe loop wakes immediately for the first pass. The source does not announce.
- **Flow source** (`internal/plugins/source/flow`) is an optional target source. It listens for NetFlow v5/v9, IPFIX, and sFlow, keeps per-prefix byte counters for a sliding window (not the raw records), and offers the top prefixes to the probe engine. Up to three of the busiest destinations in each prefix are probe candidates (#119); automatic in-prefix addresses fill in only when fewer than three were named. A destination is counted under its covering RIB prefix when the view is ready and that prefix is not a default route; otherwise it is aggregated to the configured length. The probe engine merges this set with the other sources and de-duplicates by prefix. With a `transit` block it also classifies each prefix's bytes by source address as transit (from a listed customer network) or local, and the controller passes the class to the routing policies (#29).
- **Passive problem detection** (`internal/passive`, used by the `span` source and the `flow` source's optional `problems` block) scores remote prefixes from observed TCP behavior: outbound retransmissions, handshake timeouts, remote resets, and handshake RTT from a SPAN/mirror port (AF_PACKET) or a replayed pcap, or SYN-without-ACK and RST flags from unsampled NetFlow/IPFIX. Counters are per prefix over a sliding window; packets and flow records are not stored. Problem prefixes are offered to the probe engine first (`span` marks a new one urgent for one round). They are probe targets only: nothing is announced unless the normal decision path, RIB check, and allowlist accept a measured improvement.
- **RIB view** (`internal/rib`) is an embedded GoBGP speaker with iBGP sessions to the edge routers. It records each neighbor's adj-RIB-in (the paths that neighbor advertised) and maps each prefix to its next-hop and provider (via `providers[].next_hop`). A route Packeteer injects can become this speaker's best path; that does not remove the prefix while a neighbor is still advertising it. When several neighbors advertise one prefix, the higher local preference wins. It offers exact, longest-prefix-match, and covering lookups. It is learn-only: the global export policy rejects everything and graceful restart is never enabled. The session proposes a 90s hold time so a dead peer cannot negotiate the timer off; a shorter timer from the router wins. When all sessions are down it reports not-ready and drops the learned routes, so consumers stop acting on stale data. One session going down drops only that neighbor's paths and leaves the view ready. Injection may only steer prefixes still present in this view. An optional RIB source plugin (`bmp`, #26) adds the routers' post-policy Adj-RIB-In and Loc-RIB over BMP: every provider's accepted path for a prefix, including paths the router did not select, without a full iBGP feed. Pre-policy routes (which include routes the router rejects) never make a prefix learned or pass a route check. Each provider's `bmp` usage (`off`, `prefer`, `only`) decides whether its BMP paths count. The published route prefers the iBGP path, then Loc-RIB, then the shortest BMP AS path. A route check refuses an improvement onto a provider that is not advertising the exact prefix and retires an active one. BMP paths on Packeteer's own session (BGP ID = `router_id`) or tagged with `packeteer_community` are ignored, so an injected route cannot keep itself alive. BMP never makes the view ready; a router's paths drop when its BMP session ends. BMP peers that negotiated add-path with the router are decoded with path identifiers. A neighbor with `add_path` also asks for additional paths (RFC 7911, receive only) on the iBGP session itself: the router's inactive and IX paths are held per path identifier, the native path stays visible while Packeteer's route is best, a path tagged with `packeteer_community` is ignored, and providers with `add_path` get the same route check while a session that negotiated add-path is up.
- **Decision engine** (`internal/policy`): a pure function `Decide(state, input, config, scorer, now)` that runs after every probe round, on RIB changes, and on a staleness ticker (once per probe interval) so a round that never finishes still withdraws once measurements are older than the max result age. The scorer plugin (default `weighted`) ranks the providers for each prefix. The optional `commit` scorer uses the same performance score and, when telemetry and per-prefix volume are present, also plans commit and group-balance moves. Those moves are tagged `commit`, obey the same cap, allowlist, and RIB check, and are withdrawn when the scorer is switched back to `weighted`. A loss gap under `min_loss_delta_pct` does not withdraw a commit steer. A real loss regression withdraws it at once and starts a `hold_time` cooldown. Decide refuses a higher-loss commit move unless the scorer allows it, and refuses a move onto the native provider. A scorer that does not implement planning leaves commit control off, and the decision loop does not read volumes for it. The optional `cost` scorer plans through the same path: it proposes moves tagged `cost` onto the cheapest priced provider whose path is inside its performance floor (loss and RTT limits above the best path). Decide re-checks the floor and that the destination is cheaper than native, withdraws a cost steer at once when it leaves the floor, and applies the same cap, allowlist, RIB, and cooldown rules. With `precedence: performance` a performance move wins; with `precedence: cost` a native path inside the floor is kept and a cheaper in-floor path replaces a pending performance move. A new improvement needs:
  - a native exit from the RIB (exact prefix)
  - usable, fresh measurements for the native provider and the candidate
  - a gain beyond `thresholds` (loss delta, or equal-or-better loss plus an RTT delta of at least `min_rtt_delta_ms` and, when `min_rtt_delta_pct` is set, that percent of the current path's RTT), and a lower score. A new performance move, and a switch onto a better provider, also needs `thresholds.confirm_rounds` consecutive fresh wins (default 1; a stale round does not count, a miss resets the streak including a switch off a commit or cost steer, those wins count during hold time, early probes wait a quarter of the prefix interval, a round that cannot compare does not keep the prober awake, flip-back does not wait)
  - room under `max_improvements` (biggest performance gains win, then biggest commit relief; equal relief breaks by prefix; a new performance move displaces the smallest commit steer). With the scorer's `improvement_weights` (#34), static, VIP, and performance moves inside their lane are admitted by `performance × gain + volume × Mbps` instead; weights never admit a move that failed another check and never displace an active improvement
  - no active cooldown
  - in inject mode, an allowlisted prefix

  An improvement is kept for at least `hold_time`. After that it flips back when the native path is better again, and a flip-back starts a `hold_time` cooldown so the prefix cannot flap. It switches to a clearly better alternative once that alternative has won `confirm_rounds` fresh rounds and `hold_time` has elapsed, and it retires after `improvement_ttl` so the native path gets re-measured. It is retired immediately, ignoring hold time, when its provider goes down or its data goes stale, when the provider is excluded or the prefix leaves the allowlist, when the prefix has no measurement at all, or when the RIB is not ready (every BGP session lost). A configured source dropping the prefix, such as falling out of flow top_n, does not retire it: the prefix stays a probe target until the improvement ends on its own. While an improvement is active the router normally stops advertising the native path to Packeteer (iBGP does not send a route back to the peer it was learned from, and it does not send a non-best path), so that disappearance is not a withdraw and the native provider stays the one recorded on the improvement. If the neighbor keeps advertising the prefix for 5s after the improvement is active and then withdraws it, the improvement is retired immediately and a `hold_time` cooldown blocks re-injection. That is the case when the native path stays best (the lab network statement) or the router is configured to keep sending it (`advertise-best-external`). A provider withdraw that happens only after the native path is already hidden is not visible on a single-path session; `improvement_ttl` is the backstop. With BMP (`bmp: prefer` or `only`) the native provider's post-policy path stays visible while the router hides it, and a withdraw on the steered provider fails the route check and retires the improvement at once.
- **Routing policies** (`internal/plugins/policy/*`) are optional `policy` plugins asked before each decision. For each probed prefix the controller passes the prefix, its learned AS path, and its traffic class (transit or local, from flow classification) to the chain; the first policy that matches returns a verdict (`ignore`, `allow`, `deny`, `static`, or `vip`). `maintenance` policies report the providers inside an open window. Decide applies both: forbidden providers are not usable for that prefix (native excepted), a provider in maintenance is excluded for the evaluation, `ignore` retires, `static` pins while the path is usable and inside the rule's loss/latency ceiling, and `vip` ranks ahead at the cap. Policies do not announce and cannot bypass the RIB, allowlist, cap, or withdraw rules.
- **Ops surface** (`internal/httpapi`) serves a read-only HTTP API on `http.listen` (default `127.0.0.1:8080`; empty disables it). `/healthz` is liveness. `/readyz` is readiness: startup has finished, and at least one iBGP session is up when neighbors are configured. `/metrics` is Prometheus text (probe RTT, loss, and jitter per provider and prefix, decisions, active improvements, BGP session state, and interface telemetry when it is configured). `/api/providers`, `/api/probes`, `/api/prefixes`, `/api/decisions`, `/api/improvements`, and `/api/telemetry` are JSON. `/` is an embedded dashboard with no remote assets. The server accepts GET and HEAD, except `POST /api/maintenance` and `DELETE /api/maintenance/{id}`, which open and close on-demand maintenance windows, and `POST /api/mitigations` and `DELETE /api/mitigations/{id}`, which add and remove threat mitigation rules; all are refused unless basic auth is configured. It reads probe results, decisions, session state, and telemetry snapshots; it does not announce or change policy. Prefixes that are only in the RIB, and not probed or improved, are not listed. With `http.config_editor` (#34), an admin can also write the mounted config file (`PUT /api/config`) after the same checks as a start; the running controller does not change until it restarts (or SIGHUPs, for `bgp.neighbors`). Custom dashboards (`/api/dashboards`, kept per user by the storage plugin) and scheduled report subscriptions (`internal/subscribe`, CSV by email through an `smtp` notifier) only read ([docs/ui.md](docs/ui.md)).
- **Telemetry** (`internal/plugins/telemetry/snmp`) is optional. It polls interface octet counters over SNMP v2c or v3 and keeps 95th-percentile usage for the open UTC billing period. Credentials are environment variables. A failed poll does not withdraw performance improvements. The samples are an input to `Decide` only when the scorer implements commit planning. The telemetry plugin does not announce.
- **History and reports** (`internal/history` + the `sqlite` storage plugin) are optional. The recorder takes each probe result into a daily rollup per prefix and provider, and each decision's improve, switch, and retire changes into one row per improvement with the native and chosen provider's loss and RTT at that decision, the origin ASN from the RIB view, and a country when a `rules` policy has a GeoIP database. It buffers in memory and writes once a minute and on shutdown, after the withdraw, so a slow or failing disk never delays a decision or a withdraw. Rows a previous process left open are closed on start. Reports are pure aggregations of the stored rows, served on `/api/reports` (JSON and CSV) and the dashboard. History does not announce or change a decision.
- **Announcer** (`internal/announce` + the `gobgp` plugin) publishes inject-mode improvements on the RIB view's existing iBGP session. It does not open a second session. Each route uses the chosen provider's next hop, the configured `local_pref`, `packeteer_community`, and NO_EXPORT. The announced prefix is the exact prefix in the learned RIB; Packeteer does not synthesize more-specifics, and a config that sets `more_specific_bits` is rejected. With `more_specific` on (off by default, [design](docs/design/more-specific.md)), each improvement also announces the more-specifics inside it that a neighbor advertises in the learned RIB, toward the same provider, under `more_specific.max_routes`, which counts routes on the router; they are withdrawn with the improvement or on a confirmed RIB leave. The export policy accepts only local routes that carry the Packeteer community, so learned routes are never reflected. Observe and suggest never call the announcer. A prefix is announced only when it is in the learned RIB. A route already on the wire is kept or moved while the decision engine still wants it, including when the router has hidden the native path; it is withdrawn when the engine retires the improvement (confirmed RIB leave, flip-back, expiry, a dead probe source, stale measurements, RIB session loss) and on shutdown. Graceful restart stays off. Edges must accept only the Packeteer community and must not export it to eBGP ([docs/routers.md](docs/routers.md)). With several edge routers (#27), neighbors may list the providers they forward to (`providers`) and the ones they reach through another router with the next hop to use (`next_hops`); an export policy on the one speaker then sends each router only the routes toward providers it can reach, with that router's next hop, and a provider whose every egress router session is down is unusable in Decide (`egress router down`), so its improvements are retired and withdrawn everywhere. A neighbor with neither list, such as a route reflector, gets every route ([docs/route-reflector.md](docs/route-reflector.md)). Internet exchange peers (`exchanges`) are providers with their own next hop on the peering LAN, always route-checked (the router must show the peer's own path for the exact prefix through add-path or BMP), and `/api/exchanges` reports per-peer prefixes, improvements, and unconfigured members. `bgp.as_path` puts the native or the chosen provider's learned AS path on injected routes (default empty). SIGHUP reloads `bgp.neighbors` online: sessions are added or removed on the running speaker without touching the others, and a changed per-router table replaces the export policy after withdrawing the outbound routes, which the next evaluation announces again; any other change is refused and needs a restart.
- **Inbound optimization** (`internal/inbound` + the inbound `gobgp` announcer) is optional (`inbound:`, its own mode, default `observe`). After each decision it reads telemetry and the same probe results the decider used, and steers inbound traffic for the operator's own prefixes away from a provider whose inbound 95th is over commit (commit trigger) or that is the single worst performer by mean loss or RTT (performance trigger). Damping confirms a trigger before steering, grows the hold time and cooldown of a flapping provider, and learns inertia so a commit steer is released only when demand drops; `hold_time`, `release_pct`, and `improvement_ttl` still apply; stale telemetry or missing probe results release at once and it never steers away from every provider. Triggers listed in `inbound.moderated` are only suggested. In inject it re-announces the exact learned prefix and next hop on the same iBGP session with the packeteer community, a marker, the provider's catalog prepend, withhold (selective announcement), and TE communities, and NO_EXPORT; the edge's policy applies them per session ([docs/inbound.md](docs/inbound.md)). Outbound improvements refuse inbound prefixes, and both share `max_improvements`. Steer routes are withdrawn on RIB loss and shutdown and vanish with the session on a crash.
- **Threat mitigation** (`internal/mitigation` + the mitigation `gobgp` announcer, #28) is optional (`mitigation:`, its own mode, default `observe`). Operators add RTBH (blackhole), BGP redirect, and FlowSpec (drop, rate-limit, redirect to a VRF; optionally from source countries, expanded to networks from a mounted GeoIP database) rules through `/api/mitigations` (basic auth). A rule names an exact prefix inside `mitigation.allowlist`, an action from the announcer's catalog, and a TTL; rules are in memory only, capped by `max_rules` (counted in routes), and always expire. FlowSpec rules go out as RFC 8955 NLRI whose destination is the exact learned prefix, on the same sessions (which then negotiate the FlowSpec families), and do not hold the prefix. Every rule change goes to a feed on the API, to `mitigation.*` events, and to stored history. After the outbound and inbound syncs of each round it expires rules and, in inject, announces each rule's prefix on the same iBGP session with the action's next hop (discard address or redirect target) and communities, the packeteer community, a marker, and NO_EXPORT, only while the exact prefix is in the learned RIB. While a rule holds a prefix, outbound improvements and inbound steers for it are withdrawn, so the speaker has at most one Packeteer path per prefix. Mitigation routes are withdrawn on rule removal, expiry, RIB loss, and shutdown, and vanish with the session on a crash ([docs/mitigation.md](docs/mitigation.md)).

- **Multi-POP federation** (`internal/federation` + the `mtls` federation plugin, #30) is optional (`federation:`). Each instance is one POP (`domain`). After each decision it publishes a snapshot (its own providers' health and telemetry, fresh measurements through them, its exit per learned probed prefix, and its improvements); the plugin serves it to peers over mutual TLS and polls theirs. Before each decision, fresh peer measurements through providers in their domain are merged into the input with the configured `inter_dc_rtt` added; such a provider is usable for a prefix only while its peer is fresh, RIB-ready, reports it up, and exits that exact prefix through it. `global_commit` lowers each local member's commit by the other members' fresh usage for the `commit` scorer. Nothing else changes: the allowlist, learned-RIB check, community, NO_EXPORT, cap, hold time, and withdraw rules apply, and a stale peer makes its providers unusable, so steers onto them are withdrawn. `/api/federation` is the central view. The plugin never announces ([docs/multi-pop.md](docs/multi-pop.md)).

- **Traffic anomaly detection** (`internal/anomaly` + a `detector` plugin, #33) is optional (`anomaly:`). On its own interval it reads per-prefix, per-protocol byte counters from the `flow` source, turns the deltas into rates, and feeds the detector (built-in `baseline`: EWMA mean and variance per key, tunable sensitivity, hysteresis). Every anomaly goes to a feed on `/api/anomalies`, to `anomaly.*` events, and to stored history. It never announces: an anomaly becomes a mitigation rule only when an explicit `anomaly.rules` entry matches, only for an exact prefix in the learned RIB, under `max_active` and `max_actions_per_hour`, never on an HA standby, and only through the threat mitigation controller above, with all of its checks. The rule is removed when the anomaly clears or flow data fails; state is in memory only ([docs/anomaly.md](docs/anomaly.md)).
- **High availability** (`ha:` + the `lease` elector plugin, #31) is optional. Two instances with the same config share a lease on a volume both mount. Only the active one runs decisions and announces; the outbound, inbound, and mitigation controllers check the elector under their locks before every sync, so a standby withdraws anything left and announces nothing, while it keeps its iBGP sessions, RIB view, and probes warm. An instance may lead only while its RIB view is ready. On becoming standby it withdraws at once, drops its decision state, and resigns, so the other takes over at its next renewal. A crashed instance cannot resign: the standby waits until the lease has not changed for `ttl`/2 plus the holder's recorded negotiated BGP hold time, so the routers have dropped the old routes (no graceful restart) before it announces. `packeteer -backup` and `-restore` copy the config and the storage plugin's history ([docs/ha.md](docs/ha.md)).

## Plugins

Every component above sits behind a small interface in `pkg/plugin`, selected by `type` in config: probers, target sources, scorer, routing policies, announcer (router driver), notifiers, telemetry, and storage. Built-ins register through `init()` under `internal/plugins/<kind>/<name>`. `internal/pluginhost` builds and validates the configured set at startup and runs its Start/Stop lifecycle. Out-of-process `exec` plugins (JSON over stdin/stdout) and the `webhook` notifier extend the stock container without recompiling. Events from the catalog ([docs/EVENTS.md](docs/EVENTS.md)) go through `internal/notify`, which gives each notifier its own bounded queue, filter, and rate limit, so a slow notifier never delays probing, decisions, or withdrawals. Announcers are in-process only. Telemetry does not announce. See [docs/PLUGINS.md](docs/PLUGINS.md).

```
config ──> pluginhost.Build ──> sources ─┐
                                probers ─┼─> core (stats, RIB view, decisions) ─> announcer
                                scorer  ─┤                       └──> notifiers
                               policies ─┘
                                telemetry ─> read-only API and metrics (no announce)
                    probe results + decisions ─> history ─> storage ─> /api/reports (no announce)
        peer snapshots (mTLS) ─> federation ─> merged paths + global commit ─> core (no announce)
        shared lease ─> elector ─> active? ─> gates decisions and every announcer (no announce)
```

## Modes

- `observe` — probe and score, write decisions to logs, metrics, and the read-only API, announce nothing
- `suggest` — same as observe, plus a decision feed (file/API)
- `inject` — announce allowlisted improvements

## Out of scope for M0–M3

FlowSpec (the second half of #28). Outbound commit control is the optional `commit` scorer.
